## 7.1 Was sind Punktoperationen?

### 7.1.1 Grundkonzept

Eine **Punktoperation** ist eine einfache Bildbearbeitung mit einer wichtigen Eigenschaft:

> Jeder einzelne Pixel wird *unabhängig* bearbeitet, ohne seine Nachbarn zu beeinflussen.

**Das bedeutet praktisch:**
- ✓ Jeder Pixel bekommt einen neuen Helligkeitswert
- ✓ Aber die Bildgröße bleibt gleich
- ✓ Die räumliche Struktur des Bildes bleibt erhalten

**Mathematisch formuliert:**
Ein neuer Pixelwert $a'$ wird berechnet, indem man den alten Pixelwert $a$ in eine Funktion $f$ einsetzt:

$$
a' = f(a)
$$

**Praktische Beispiele aus dem Alltag:**
- Helligkeit erhöhen oder senken
- Kontrast verändern
- Bild invertieren (Fotografie → Negativ)
- Schwarz-Weiß Konvertierung

### 7.1.2 Zwei Arten von Punktoperationen: Homogen und Nicht-Homogen

Es gibt zwei grundlegend unterschiedliche Ansätze für Punktoperationen:

#### **Homogene Punktoperationen** (Schwerpunkt dieser Vorlesung)

Die Funktion hängt **nur** vom alten Pixelwert ab:

$$
a' = f(a)
$$

**Merkmal:** Die gleiche Operation wird auf alle Pixel angewendet — egal wo sie sich im Bild befinden.

**Beispiel:** "Erhöhe die Helligkeit *im gesamten* Bild um 10 Stufen"
- Ein dunkles Pixel (z.B. Wert 50) wird zu 60
- Ein helles Pixel (z.B. Wert 200) wird zu 210
- Alle Pixel erhalten die **gleiche** Helligkeitssteigerung

#### **Nicht-Homogene Punktoperationen** (werden nur kurz erwähnt)

Die Funktion hängt vom Pixelwert **und** von seiner Position ab:

$$
a' = g(a, u, v)
$$

wobei $u, v$ die Bildkoordinaten (Position) angeben.

**Merkmal:** Die Operation hängt davon ab, *wo* ein Pixel sitzt.

**Beispiel:** "Erhöhe den Kontrast in der Bildmitte stärker als am Rand"
- Ein dunkles Pixel in der Mitte könnte stärker aufgehellt werden
- Das gleiche dunkle Pixel am Rand könnte weniger aufgehellt werden
- Die Position bestimmt die Wirkung mit

> [!tip] Fokus dieser Vorlesung
> **Wir behandeln nur homogene Punktoperationen!** Das vereinfacht vieles und ist für die meisten Bildbearbeitungs-Aufgaben ausreichend.

## 7.3 **Kontrast und Helligkeit anpassen**

### 7.3.1 Grundkonzept: Zwei einfache Operationen

Um ein Bild zu verändern, haben wir zwei Basis-Operationen:

**1. Helligkeit ändern (Addition)**

Addiere einen festen Wert zu jedem Pixel hinzu:

$$
f_{\mathrm{b}}(a) = a + 10
$$

**Bedeutung:** Jeder Pixel wird um 10 Helligkeitsstufen aufgehellt.

**Praktisches Beispiel:**
- Pixel mit Wert 50 → wird zu 60 (also 50 + 10)
- Pixel mit Wert 200 → wird zu 210 (also 200 + 10)
- Das ganze Bild wird gleichmäßig heller

**2. Kontrast ändern (Multiplikation)**

Multipliziere jeden Pixel mit einem festen Faktor:

$$
f_{\rm c}(a) = a \cdot 1.5
$$

**Bedeutung:** Jeder Pixel wird 1,5-mal so hell (Kontrast erhöht sich).

**Praktisches Beispiel:**
- Pixel mit Wert 100 → wird zu 150 (also 100 × 1,5)
- Pixel mit Wert 200 → wird zu 300 (aber Achtung: zu hell!)
- Dunkle Bereiche werden heller, helle Bereiche noch heller (größere Unterschiede)

### 7.3.2 Problem: Clamping (Werte begrenzen)

Es gibt ein Problem: Bildpixel dürfen nur Werte zwischen **0 und 255** haben!

**Das Problem in der Praxis:**
Wenn wir einen Pixel mit Wert 200 mit 1,5 multiplizieren, erhalten wir 300 — aber das ist unmöglich!

**Die Lösung: Clamping**

> **Clamping** bedeutet: Begrenze alle zu hohen oder zu niedrigen Werte auf die erlaubten Grenzen.

$$
\text{Begrenzt}(x) = \begin{cases}
0 & \text{wenn } x < 0 \\
x & \text{wenn } 0 \leq x \leq 255 \\
255 & \text{wenn } x > 255
\end{cases}
$$

**Praktisches Beispiel:**
- Wenn ein Pixel nach Bearbeitung den Wert 300 hätte → wird zu **255** (reinweiß, also begrenzt)
- Wenn ein Pixel nach Bearbeitung den Wert -5 hätte → wird zu **0** (reinschwarz, also begrenzt)
- Werte im Bereich 0–255 bleiben unverändert

### 7.3.3 Programmcode-Beispiel

Hier ist ein praktisches Beispiel für eine Kontrasterhöhung um 50% **mit Clamping**:

```java
// Durchlaufe alle Zeilen
for (int v = 0; v < height; v++) {
    // Durchlaufe alle Spalten einer Zeile
    for (int u = 0; u < width; u++) {
        // Hole alten Pixelwert
        int oldValue = image.getPixel(u, v);
        
        // Berechne neuen Wert (Kontrast × 1.5)
        int newValue = (int)(oldValue * 1.5);
        
        // Clamping: Begrenze auf [0, 255]
        if (newValue > 255) newValue = 255;
        if (newValue < 0) newValue = 0;
        
        // Speichere neuen Pixelwert
        image.setPixel(u, v, newValue);
    }
}
```

**Was passiert in diesem Code:**
1. Jeder Pixel wird mit 1,5 multipliziert
2. Wenn das Ergebnis größer als 255 ist → wird es 255 (Clamping)
3. Der neue Wert wird ins Bild geschrieben

## 7.4 **Invertierung (Negativbild erzeugen)**

### 7.4.1 Grundidee

Invertierung kehrt die Helligkeitsverteilung um:
- Was dunkel war, wird hell
- Was hell war, wird dunkel
- Das Ergebnis sieht aus wie das Negativ einer Fotografie

### 7.4.2 Mathematik

Die Formel ist sehr einfach:

$$
f_{\text{inv}}(a) = a_{\text{max}} - a = 255 - a
$$

**Erklärung:**
- Subtrahiere jeden Pixelwert von 255
- Ein schwarzer Pixel (0) wird zu Weiß (255 − 0 = 255)
- Ein weißer Pixel (255) wird zu Schwarz (255 − 255 = 0)
- Ein mittleres Grau (128) wird zu inversem Grau (255 − 128 = 127)

**Praktisches Beispiel:**

| Alter Wert | Neuer Wert | Farbe |
|-----------|-----------|-------|
| 0 | 255 | Schwarz → Weiß |
| 100 | 155 | Dunkelgrau → Hellgrau |
| 128 | 127 | Grau → Grau (nahe Inverse) |
| 200 | 55 | Hellgrau → Dunkelgrau |
| 255 | 0 | Weiß → Schwarz |

## 7.5 **Schwellwertbildung (Thresholding)**

### 7.5.1 Grundidee

Schwellwertbildung ist eine extrem einfache Entscheidungsregel:

> **Regel:** Vergleiche jeden Pixelwert mit einer **Schwelle**. Je nachdem, ob er darunter oder darüber liegt, färbe ihn dunkel oder hell.

**Das bedeutet praktisch:**
- Alle dunklen Pixel (unter der Schwelle) werden zu Schwarz (0)
- Alle hellen Pixel (über der Schwelle) werden zu Weiß (255)
- Das Ergebnis ist immer ein **reines Schwarz-Weiß-Bild**

### 7.5.2 Mathematische Formulierung

Wähle einen Schwellenwert $a_{\text{th}}$. Die Formel ist dann:

$$
f_{\text{threshold}}(a) = \begin{cases}
a_0 & \text{wenn } a < a_{\text{th}} \\
a_1 & \text{wenn } a \geq a_{\text{th}}
\end{cases}
$$

**Die Variablen:**
- $a$ = alter Pixelwert (0 bis 255)
- $a_{\text{th}}$ = Schwellenwert (z.B. 128)
- $a_0$ = Wert für dunkle Pixel (meist 0 = schwarz)
- $a_1$ = Wert für helle Pixel (meist 255 = weiß)

### 7.5.3 Praktisches Beispiel: Schwarz-Weiß-Konvertierung

**Szenario:** Wir haben ein Graustufenbild und wollen es in Schwarz-Weiß umwandeln mit $a_{\text{th}} = 128$.

**Das Ergebnis:**

| Alter Wert | Vergleich | Neuer Wert |
|-----------|-----------|-----------|
| 0 bis 127 | < 128 | 0 (Schwarz) |
| 128 bis 255 | ≥ 128 | 255 (Weiß) |

**Konkrete Beispiele:**
- Pixel mit Wert 50 → ist kleiner als 128 → wird zu 0 (schwarz)
- Pixel mit Wert 100 → ist kleiner als 128 → wird zu 0 (schwarz)
- Pixel mit Wert 128 → ist gleich 128 → wird zu 255 (weiß)
- Pixel mit Wert 200 → ist größer als 128 → wird zu 255 (weiß)

### 7.5.5 Programmcode-Beispiel

```java
// Schwellwertbildung mit Schwelle 128

    for (int u = 0; u < width; u++) {
        int pixelValue = image.getPixel(u, v);

        } else {

        }

    }
}
```

> Schwellwertbildung wird verwendet für:
> - **Dokumenten-Scans:** Schwarze Schrift auf weißem Papier
> - **Zeilenzeichnung:** Konvertiere sketchy Zeichnungen in saubere Linien
> - **Bildanalyse:** Trenne Objekte vom Hintergrund
> - **Binarisierung:** Umwandlung in das einfachste Bildformat

## 7.6 **Automatische Kontrastanpassung (Autokontrast)**

### 7.6.1 Das Problem: Untergenutzte Helligkeit

Oft nutzt ein Foto nicht den vollen Helligkeitsbereich. Zum Beispiel:

- Ein Foto hat die dunkelsten Pixel bei Wert **50** (statt 0)
- Die hellsten Pixel sind bei Wert **200** (statt 255)
- Das Foto wirkt "flau" und grau, obwohl es mehr Kontrast haben könnte

**Visuelle Beispiele:**

![[7-_page_10_Picture_2.jpeg]] → (Foto mit geringem Kontrast)
![[7-_page_10_Figure_4.jpeg]] → (Nach Autokontrast: klarer und lebendiger)

**Das Histogramm zeigt das Problem:**
- Statt von 0 bis 255 nutzt es nur den Bereich 50 bis 200
- Das bedeutet verschwendete Helligkeitsstufen

### 7.6.2 Grundidee: Strecke das Histogramm

> **Autokontrast** macht folgendes: **Strecke den Helligkeitsbereich des Bildes automatisch auf die volle Spanne 0 bis 255.**

**Das ist wie ein Gummiband:**
- Das dunkelste Pixel im Bild wird zu Schwarz (0)
- Das hellste Pixel im Bild wird zu Weiß (255)
- Alle anderen Pixel werden proportional dazwischen verteilt

### 7.6.3 Mathematik des Autokontrastsr

**Schritt 1:** Finde die Extremwerte im Bild

$$
a_{\text{low}} = \min(a) \quad \text{(dunkelster Pixelwert)}
$$
$$
a_{\text{high}} = \max(a) \quad \text{(hellster Pixelwert)}
$$

**Beispiel:** Wenn das dunkelste Pixel 50 und das hellste 200 ist:
- $a_{\text{low}} = 50$
- $a_{\text{high}} = 200$

**Schritt 2:** Berechne neue Pixelwerte mit der Autokontrast-Formel

$$
a' = \frac{a - a_{\text{low}}}{a_{\text{high}} - a_{\text{low}}} \cdot 255
$$

**Erklärung der Formel:**
1. $(a - a_{\text{low}})$ verschiebt den Wert so, dass der dunkelste Punkt bei 0 beginnt
2. Die Division durch $(a_{\text{high}} - a_{\text{low}})$ normalisiert auf den Bereich 0 bis 1
3. Die Multiplikation mit 255 streckt den Bereich auf 0 bis 255

**Praktisches Rechnen-Beispiel:**

Gegeben: $a_{\text{low}} = 50$, $a_{\text{high}} = 200$, Pixel mit Wert $a = 125$

$$
a' = \frac{125 - 50}{200 - 50} \cdot 255 = \frac{75}{150} \cdot 255 = 0.5 \cdot 255 = 127.5 ≈ 128
$$

**Tabelle mit mehreren Beispielen:**

| Alter Wert | Berechnung | Neuer Wert |
|-----------|-----------|-----------|
| 50 (dunkelster) | (50−50)/(200−50) × 255 | 0 (schwarz) |
| 100 | (100−50)/(200−50) × 255 | 85 |
| 125 (Mitte) | (125−50)/(200−50) × 255 | 128 |
| 150 | (150−50)/(200−50) × 255 | 170 |
| 200 (hellster) | (200−50)/(200−50) × 255 | 255 (weiß) |

### 7.6.4 Programmcode-Beispiel

```java
// Autokontrast berechnen
int minValue = 255, maxValue = 0;

// Schritt 1: Finde Min und Max
for (int v = 0; v < height; v++) {
    for (int u = 0; u < width; u++) {
        int value = image.getPixel(u, v);
        if (value < minValue) minValue = value;
        if (value > maxValue) maxValue = value;
    }
}

// Schritt 2: Berechne neue Werte
int range = maxValue - minValue;
if (range > 0) {  // Prüfe, dass nicht alle Pixel gleich sind
    for (int v = 0; v < height; v++) {
        for (int u = 0; u < width; u++) {
            int oldValue = image.getPixel(u, v);
            int newValue = (int)((oldValue - minValue) * 255.0 / range);
            image.setPixel(u, v, newValue);
        }
    }
}
```

## 7.7 **Modifizierte Autokontrastfunktion (Robuste Variante)**

### 7.7.1 Das Problem mit normalem Autokontrast

Das normale Autokontrast hat ein großes Problem:

**Ein einzelner extremer Pixel kann alles ruinieren!**

**Praktisches Szenario:**
- Ein Foto hat meistens Pixel im Bereich 50 bis 200 (sinnvoll verteilt)
- Aber durch Kamerarauschen gibt es einen einzelnen **schwarzen Pixel (Wert 0)** und einen **weißen Pixel (Wert 255)**
- Der normale Autokontrast nutzt genau diese Extremwerte für Min/Max
- Das Ergebnis: Die meisten Pixel werden zusammengequetscht, das Bild sieht IMMER NOCH flau aus!

![[7-_page_14_Figure_8.jpeg]]

Die wenigen Ausreißer-Pixel führen nicht zu guter Kontrastanpassung. **Besser wäre es, diese Extrempixel zu ignorieren!**

### 7.7.2 Lösung: Nutze repräsentative Pixel statt Extremwerte

Die **modifizierte Autokontrastfunktion** ignoriert die extremen Ausreißer:

**Die Idee in 3 Schritten:**

1. **Entscheide, welche Pixel zu ignorieren sind**
   - Ignoriere die dunkelsten 1% der Pixel
   - Ignoriere die hellsten 0,5% der Pixel
   - (Diese Werte sind einstellbar)

2. **Finde die neuen Grenzen**
   - Bestimme $\hat{a}_{\text{low}}$: den Helligkeitswert, unter dem 1% der Pixel liegen
   - Bestimme $\hat{a}_{\text{high}}$: den Helligkeitswert, über dem 0,5% der Pixel liegen

3. **Nutze diese neuen Grenzen statt Min/Max**
   - Kontrast wird basierend auf repräsentativen 98,5% der Pixel berechnet
   - Nicht basierend auf wenigen extremen Ausreißern

**Praktisches Beispiel:**
- Bild hat 10.000 Pixel
- 1% der dunkelsten = 100 Pixel (werden ignoriert)
- 0,5% der hellsten = 50 Pixel (werden ignoriert)
- Die restlichen **9.850 Pixel** (98,5%) definieren den neuen Helligkeitsbereich

![[7-_page_15_Figure_5.jpeg]]

### 7.7.3 Mathematische Formel

$$
f_{\text{mac}}(a) = \begin{cases} 
0 & \text{wenn } a \leq \hat{a}_{\text{low}} \\[0.5em]
\dfrac{a - \hat{a}_{\text{low}}}{\hat{a}_{\text{high}} - \hat{a}_{\text{low}}} \cdot 255 & \text{wenn } \hat{a}_{\text{low}} < a < \hat{a}_{\text{high}} \\[0.5em]
255 & \text{wenn } a \geq \hat{a}_{\text{high}}
\end{cases}
$$

**Was bedeutet jeder Fall:**
- **Oben:** Alle Pixel unter $\hat{a}_{\text{low}}$ werden auf Schwarz (0) gesetzt
- **Mitte:** Pixel im relevanten Bereich werden wie beim normalen Autokontrast gestreckt
- **Unten:** Alle Pixel über $\hat{a}_{\text{high}}$ werden auf Weiß (255) gesetzt

### 7.7.4 Vergleich: Normal vs. Modifiziert

| Eigenschaft | Normaler Autokontrast | Modifizierter Autokontrast |
|-------------|----------------------|---------------------------|
| **Min/Max** | Nutzt absolute Extrema | Ignoriert 1% Extrempixel |
| **Robustheit** | Anfällig für Rauschen & Ausreißer | Robust gegen einzelne Fehler |
| **Praktisches Ergebnis** | Manchmal immer noch zu schwach | Meist deutlich besseres Resultat |
| **Beste Verwendung** | Hochwertige Studio-Fotos | Schnelle Foto-Vorschau, echte Bilder |

### 7.7.5 Typische Parameter in der Praxis

- $s_{\text{low}} = 1\%$ (ignoriere 1% dunkelste Pixel)
- $s_{\text{high}} = 0.5\%$ bis $1.5\%$ (ignoriere hellste Pixel)

> [!tip] 
> Diese Werte funktionieren gut für die meisten realen Fotos. Manche Software erlaubt dem Benutzer, diese Prozentwerte einzustellen für noch bessere Ergebnisse.

### 7.7.6 Übungsaufgabe: Autokontrast berechnen

**Gegeben:** Ein 16-Bit-Grauwertbild mit folgendem Histogramm

## 7.9 **Histogrammanpassung (Histogram Matching)**

### 7.9.1 Das Problem: Unterschiedliche Helligkeitsverteilungen

Stell dir vor, du hast mehrere Fotos der gleichen Szene, aber:
- Foto 1 ist zu dunkel (verschobenes Histogramm)
- Foto 2 hat normalen Kontrast
- Foto 3 ist zu hell

**Das Problem:** Alle drei Fotos sehen unterschiedlich aus, obwohl sie die gleiche Szene zeigen. Das ist unerwünscht bei:
- **Druckwerk:** Alle Bilder sollen einheitlich aussehen
- **Bildvergleich:** Schwierig, wenn die Helligkeiten nicht passen

![[7-_page_20_Picture_2.jpeg]]

### 7.9.2 Die Lösung: Histogrammanpassung

> **Histogrammanpassung** bedeutet: Ändere die Helligkeitsverteilung eines Bildes so, dass sie einer **Referenzverteilung** entspricht.

**Das funktioniert so:**

**Schritt 1:** Wähle ein Referenzbild oder eine Referenzverteilung
- Das kann ein anderes Foto sein
- Oder eine mathematische Verteilung (z.B. Gaußsche Glocke)

**Schritt 2:** Berechne eine Transformationsfunktion
- Diese Funktion ordnet jedem Pixelwert des Originalbilds einen neuen Wert zu
- Ziel: Das neue Histogramm gleicht dem Referenzhistogramm

**Schritt 3:** Wende die Transformation an
- Jeder Pixel wird mit der Transformationsfunktion umgewandelt
- Das Ergebnis: Ein Bild mit ähnlicher Helligkeitsverteilung wie die Referenz

### 7.9.3 Beispiel 1: Histogrammanpassung mit vordefinierter Verteilung

Manchmal möchte man eine bestimmte mathematische Verteilung nutzen (z.B. eine Gaußglocke):

![[7-_page_21_Figure_1.jpeg]]

**Vorteil:** Vorhersagbares Ergebnis, da die Zielverteilung bekannt ist.

### 7.9.4 Beispiel 2: Histogrammanpassung anhand eines Referenzbildes

Oft hat man ein "ideales" Referenzbild und möchte andere Bilder daran anpassen:

![[7-_page_22_Figure_1.jpeg]]

**Vorteil:** Alle Fotos einer Serie können dieselbe Helligkeit bekommen.

### 7.9.5 Mathematische Grundidee

Die Mathematik hinter Histogrammanpassung nutzt die **Verteilungsfunktion** (auch: kumulatives Histogramm) aus [[6. Histogramme]]:

- Berechne die Verteilungsfunktion $P_A$ des Originalbildes
- Berechne die Verteilungsfunktion $P_R$ des Referenzbildes oder der Referenzverteilung
- Die Transformationsfunktion ist dann: $a' = P_R^{-1}(P_A(a))$

Das ist ein mathematisches Konzept — die praktische Umsetzung wird in **Teil B** dieser Vorlesung behandelt.

## Review & Learning — Teil A

> [!summary] Zusammenfassung der wichtigsten Konzepte
> 
> **Was ist eine homogene Punktoperation?**
> - Jeder Pixel wird **unabhängig** von seinen Nachbarn verarbeitet
> - Der neue Pixelwert hängt nur vom alten Wert ab: $a' = f(a)$
> - Größe, Form und räumliche Struktur des Bildes bleiben erhalten
>
> **Die fünf wichtigsten Operationen:**
> 
> 1. **Kontrast und Helligkeit anpassen**
>    - Addition: $a' = a + b$ (gleichmäßig heller/dunkler)
>    - Multiplikation: $a' = a \cdot k$ (Kontrast ändern)
>    - Clamping: Werte auf [0, 255] begrenzen
>
> 2. **Invertierung**
>    - Umkehrung: $a' = 255 - a$ (Negativbild)
>    - Dunkel wird hell, hell wird dunkel
>
> 3. **Schwellwertbildung**

>    - Formel: $a' = 0$ wenn $a < a_{\text{th}}$, sonst $a' = 255$

>    - Automatisch Min und Max finden
>    - Den Bereich auf [0, 255] strecken

>    - Ignoriert die extremsten 1-2% der Pixel
>    - Weniger anfällig für Rauschen und Ausreißer
>    - Bessere Ergebnisse für echte Fotos
>
> **Histogrammanpassung**
> - Ändert die Helligkeitsverteilung eines Bildes
> - Ziel: Angleichung an Referenzverteilung oder Referenzbild
> - Wichtig für einheitliche Bildserien

## 7.10 **Histogrammanpassung: Mathematische Grundlagen**

### 7.10.1 Das Problem: Formale Darstellung

Gegeben sind:
- Das **Originalbild** mit Verteilungsfunktion $P_A$ (vom englischen "actual")
- Eine **Referenzverteilung** $P_R$ (vom englischen "reference")

Gesucht ist:
- Eine Transformationsfunktion $f_{hs}$, die das Originalbild so verändert, dass die neue Verteilung der Referenzverteilung gleicht

**Mathematisch:**
$$
a' = f_{hs}(a) \quad \text{mit} \quad P_R(a') = P_A(a)
$$

**Die elegante Lösung:**
$$
a' = f_{hs}(a) = P_R^{-1}(P_A(a))
$$

**Was das bedeutet:**
1. Berechne $P_A(a)$ — wie viel Prozent der Pixel sind dunkler als der aktuelle Pixel
2. Nutze die Umkehrfunktion $P_R^{-1}$ um in der Referenzverteilung den entsprechenden Wert zu finden
3. Das Ergebnis ist der neue Pixelwert

![[7b-_page_3_Figure_1.jpeg]]

### 7.10.2 Visuelle Erklärung des Prinzips

![[7b-_page_5_Figure_1.jpeg]]

**Die drei Schritte visuell:**
1. **Schritt 1:** Berechne die kumulative Verteilung des Originalbildes ($P_A$)
2. **Schritt 2:** Berechne die kumulative Verteilung der Referenz ($P_R$)
3. **Schritt 3:** Verbinde die beiden durch die Umkehrfunktion ($P_R^{-1}$)

## 7.11 **Stückweise lineare Referenzverteilungen**

In der Praxis nutzt man oft keine beliebig komplexe mathematische Verteilung, sondern **stückweise lineare Funktionen**. Das ist praktisch und einfach zu handhaben.

### 7.11.1 Beschreibung einer stückweisen linearen Funktion

Eine stückweise lineare Funktion wird durch Koordinatenpaare definiert:

$$
P_L(i) = \{(i_0, q_0), (i_1, q_1), \ldots, (i_N, q_N)\}
$$

**Erklärung:**
- Die Funktion verbindet die Punkte $(i_0, q_0)$, $(i_1, q_1)$, etc. mit **geraden Linien**
- Zwischen den Punkten erfolgt **lineare Interpolation**
- Die Funktion muss **streng monoton steigend** sein (damit die Umkehrfunktion existiert)

**Praktisches Beispiel:**
- Punkt 0: $(0, 0)$ — bei Pixelwert 0 sind 0% der Pixel dunkler
- Punkt 1: $(128, 0.5)$ — bei Pixelwert 128 sind 50% der Pixel dunkler
- Punkt 2: $(255, 1)$ — bei Pixelwert 255 sind 100% der Pixel dunkler

![[7b-_page_2_Figure_4.jpeg]]

### 7.11.2 Umkehrfunktion für stückweise lineare Funktionen

Die Umkehrfunktion $P_L^{-1}(b)$ wird benötigt um die Histogrammanpassung durchzuführen:

$$
a' = f_{hs}(a) = P_L^{-1}(b) = P_L^{-1}(P_A(a))
$$

**Für jedes Segment $n$ zwischen $(i_n, q_n)$ und $(i_{n+1}, q_{n+1})$ gilt:**

$$
P_L^{-1}(b) = i_n + (b - q_n) \cdot \frac{i_{n+1} - i_n}{q_{n+1} - q_n} \quad \text{für } q_n \leq b < q_{n+1}
$$

**An den Grenzen:**
- Falls $b < q_0$: setze $a' = 0$
- Falls $b \geq q_N$: setze $a' = K-1$

**Was die Formel macht:**
- Sie interpoliert **linear** zwischen den Kontrollpunkten
- Das Ergebnis ist eine stetige Transformationsfunktion

---

## 7.12 **Histogrammausgleich — Ein Spezialfall**

### 7.12.1 Was ist Histogrammausgleich?

Histogrammausgleich ist ein **Sonderfall** der Histogrammanpassung, bei dem die Referenzverteilung eine **Gleichverteilung** ist.

**Ziel:** Die Intensitätswerte sollen möglichst gleichmäßig über den ganzen Bereich verteilt sein.

**Referenzverteilung:** 
$$
P_L(i) = P_{\text{eq}}(i) = \begin{cases}
0 & \text{bei } i = 0 \\
1 & \text{bei } i = K-1
\end{cases}
$$

Das ist die einfachste stückweise lineare Funktion: eine **Gerade von (0,0) zu (K-1, 1)**.

### 7.12.2 Die Formel für Histogrammausgleich

Die Umkehrfunktion ist:
$$
P_{\text{eq}}^{-1}(b) = b \cdot (K - 1)
$$

Also wird jeder Pixel transformiert zu:
$$
a' = f_{\text{eq}}(a) = P_A(a) \cdot (K-1)
$$

Da wir nur ganzzahlige Pixelwerte haben:
$$
f_{\text{eq}}(a) = \left\lfloor P_A(a) \cdot (K-1) \right\rfloor
$$

wobei $\lfloor \cdot \rfloor$ die Abrundungsfunktion ist.

### 7.12.3 Visuelle Beispiele

![[7b-_page_6_Figure_1.jpeg]]
![[7b-_page_7_Picture_1.jpeg]]

**Beobachtung:** 
- **Vorher:** Das Histogramm ist ungleichmäßig (z.B. viele dunkle Pixel, wenige helle)
- **Nachher:** Das Histogramm ist flacher und breiter verteilt

### 7.12.4 Eigenschaften des Histogrammausgleichs

**Vorteile:**
- ✓ Einfach zu berechnen
- ✓ Vollautomatisch (keine Parameterisierung nötig)
- ✓ Monoton steigend — **Pixelreihenfolge bleibt erhalten** ($a_1 < a_2 \Rightarrow a'_1 \leq a'_2$)
- ✓ Idempotent — wiederholte Anwendung ändert das Ergebnis nicht

**Nachteile:**
- ✗ Dynamikverlust durch Aufsummieren — das kumulative Histogramm verliert Information
- ✗ Gleichverteilung ist für Fotografien unrealistisch — das menschliche Auge mag ausgewogene, nicht vollkommen flache Histogramme

> [!warning] Wichtig
> Histogrammausgleich funktioniert bei manchen Fotos wunderbar, bei anderen wirkt das Ergebnis künstlich überbearbeitet. Es lohnt sich, das Ergebnis immer anzusehen!

## 7.13 **Alternative Verfahren für komplexe Referenzverteilungen**

### 7.13.1 Das Problem bei nicht-monotonen Referenzverteilungen

Was passiert, wenn die Referenzverteilung **nicht streng monoton steigend** ist?

**Problem:** Die Umkehrfunktion $P_R^{-1}$ existiert nicht!

**Beispiel:** Eine bimodale Verteilung (zwei Spitzen) kann nicht einfach invertiert werden.

![[7b-_page_9_Figure_4.jpeg]]

### 7.13.2 Lösung: Sukzessives Auffüllen

**Idee:** Statt die Umkehrfunktion zu berechnen, wird die Referenzverteilung iterativ mit Pixeln aus dem Originalbild "aufgefüllt".

**Das Verfahren:**
1. Sortiere alle Pixel des Originalbildes nach Helligkeit
2. Sortiere auch die Referenzverteilung
3. Ordne die $i$-ten Pixel des Originals den $i$-ten Positionen der Referenz zu

**Vorteil:** Funktioniert auch für nicht-monotone Verteilungen

## 7.14 **Gammafunktion — Nicht-lineare Intensitätstransformation**

### 7.14.1 Herkunft: Aus der analogen Fotografie

Die Gammafunktion kommt ursprünglich aus der analogen Fototechnik:

**In Kameras und Filmen:**
- **Belichtungsstärke B** = wie viel Licht auf den Film/Sensor trifft
- **Filmdichte D** = wie dunkel der entwickelte Film ist
- Der Zusammenhang ist **nicht linear**, sondern folgt einer **Potenzfunktion** (exponentiell oder logarithmisch)

![[7c-_page_1_Figure_4.jpeg]]

Diese mathematische Beziehung nennt man **Gamma-Korrektur**.

### 7.14.2 Die Gammafunktion: Mathematische Definition

Die Gammafunktion ist eine **Potenztransformation**:

$$
a' = f_{\gamma}(a) = a^{\gamma} \quad \text{für } \gamma > 0
$$

**Was bedeutet der Exponent $\gamma$?**

- **$\gamma < 1$** (z.B. 0,5): Die Kurve ist **konkav** — dunkle Werte werden stark aufgehellt
- **$\gamma = 1$**: Lineare Identität — keine Änderung ($a' = a$)
- **$\gamma > 1$** (z.B. 2,0): Die Kurve ist **konvex** — dunkle Werte werden weniger aufgehellt

**Visuelle Beispiele:**

| Gamma-Wert | Effekt | Anwendung |
|-----------|--------|----------|
| $\gamma = 0.5$ | Aufhellung (logarithmisch) | Unterbelichtete Fotos |
| $\gamma = 1.0$ | Keine Änderung | Referenzfall |
| $\gamma = 2.0$ | Verdunklung (quadratisch) | Überbelichtete Fotos |
| $\gamma = 5.0$ | Starke Verdunklung | Extreme Anpassungen |

![[7c-_page_1_Figure_4.jpeg]]

### 7.14.3 Eigenschaften der Gammafunktion

**Mathematische Eigenschaften:**

✓ **Streng monoton steigend** — die Funktion wird immer größer
- Wenn $a_1 < a_2$, dann $f_{\gamma}(a_1) < f_{\gamma}(a_2)$
- Das bedeutet: **Pixelreihenfolge bleibt erhalten**

✓ **Leicht invertierbar** — die Umkehrfunktion ist auch wieder eine Gammafunktion!

$$
a = f_{\gamma}^{-1}(a') = (a')^{1/\gamma}
$$

Das heißt: Die Umkehrung hat einfach den umgekehrten Exponenten.

**Beispiel:**
- Wenn $\gamma = 0.5$ (Aufhellung), dann ist die Umkehrung $\gamma = 2$ (Verdunklung)
- Wenn du eine Aufhellung mit $\gamma = 0.5$ machst und dann mit $\gamma = 2$ rückgängig machst, bekommst du das Original zurück

## 7.15 **Gammawerte in der Praxis — Industrie-Standards**

### 7.15.1 Alte Monitore (Röhren-Technologie)

In der klassischen CRT-Technologie (Kathodenstrahlröhren) gemessen:
- Typisc **Gammawert: 1,8 bis 2,8**
- Genaue Messwerte variierten je nach Modell

### 7.15.2 Fernseh-Standards (PAL & NTSC)

Diese etablierten Standards definieren:

**PAL (Europa):**
- Wiedergabegeräte (Fernseher): **$\gamma = 2.2$**
- Praktisch gemessen: etwa **$\gamma = 2.35$**

**NTSC (Nordamerika):**
- Wiedergabegeräte: **$\gamma = 2.8$**
- Praktisch gemessen: etwa **$\gamma = 2.35$** (ähnlich wie PAL)

**Aufnahmegeräte (Kameras):**
- Standard: **$\gamma \approx 0.45$**
- Das ist ungefähr die Umkehrung von 2.2 (denn $1/2.2 \approx 0.45$)

### 7.15.3 Internationale Norm ITU-R BT 709

Die moderne ITU-R BT 709 Standard definiert:

**Wiedergabegeräte:**
- Gamma-Wert: **2.5**

**Aufnahmegeräte (Kameras):**
- Gamma-Wert: **0.51** (modifiziert, nicht reine Exponentialfunktion)

### 7.15.4 Computer und Monitore

**Moderne Bildschirme:**
- Gammawert ist **softwareseitig einstellbar**
- Typischer Wert: 2.2 (für Kompatibilität mit TV-Standards)

> [!info] Wichtig

## 7.16 **Gammakorrektur: Praktische Anwendung**

### 7.16.1 Das Problem: Geräte-Transfercharakteristik

**Szenario:** Eine Kamera mit bekanntem Gammawert $\gamma_c = 2.2$ fotografiert eine Szene mit Lichtintensität $B$.

**Die Kamera produziert ein Signal:**
$$
s = B^{\gamma_c} = B^{2.2}
$$

**Problem:** Das Signal ist verzerrt! Die hellen Bereiche wurden zu stark abgedimmt.

### 7.16.2 Die Lösung: Inverse Gamma-Korrektur

**Idee:** Nutze die **Umkehrfunktion**, um die Kamera-Verzerrung zu kompensieren.

**Wende die Umkehrfunktion an:**
$$
b = f_{\bar{\gamma}_c}(s) = s^{1/\gamma_c} = s^{1/2.2} = s^{0.45}
$$

**Das Ergebnis:**
$$
b = s^{1/\gamma_c} = (B^{\gamma_c})^{1/\gamma_c} = B^{(\gamma_c \cdot \frac{1}{\gamma_c})} = B^1 = B
$$

Das heißt: **Das Signal ist jetzt wieder proportional zur originalen Lichtintensität!**

### 7.16.3 Praktische Implementierung mit Normierung

In der Praxis normalisiert man die Pixelwerte zuerst auf [0,1], wendet Gamma an, und skaliert dann zurück:

$$
a' = f_{gc}(a, \gamma) = \left(\frac{a}{a_{\text{max}}}\right)^{\gamma} \cdot a_{\text{max}}
$$

**Schritt für Schritt:**
1. **Normieren:** $\tilde{a} = \frac{a}{255}$ (Bereich 0 bis 1)
2. **Gamma anwenden:** $\tilde{a}' = \tilde{a}^{\gamma}$
3. **Zurückskalieren:** $a' = \tilde{a}' \cdot 255$

**Programmcode-Beispiel:**
```java
double gamma = 0.45;  // Inverse von 2.2
for (int v = 0; v < height; v++) {
    for (int u = 0; u < width; u++) {
        double normalized = image.getPixel(u,v) / 255.0;
        double corrected = Math.pow(normalized, gamma);
        int newValue = (int)(corrected * 255);
        image.setPixel(u, v, newValue);
    }
}
```

## 7.17 **Nachteile der Gammafunktion und die Lösung**

### 7.17.1 Das Problem: Verhalten bei kleinen Werten

Die reine Gammafunktion hat ein großes Problem bei **sehr dunklen Pixelwerten** (nahe Null).

**Mathematisch:** Die erste Ableitung an der Stelle Null ist:

$$
f'_{\gamma}(0) = \begin{cases} 
0 & \text{für } \gamma > 1 \\
1 & \text{für } \gamma = 1 \\
\infty & \text{für } \gamma < 1
\end{cases}
$$

**Was das bedeutet:**

- **Wenn $\gamma > 1$:** Sehr dunkle Pixel werden fast auf Schwarz abgebildet (Anstieg = 0)
- **Wenn $\gamma < 1$:** Sehr dunkle Pixel werden **extrem stark verstärkt** (Anstieg = ∞)
- **Beide Fälle sind problematisch:** Ein kleine Variation in sehr dunklen Bildbereichen wird entweder völlig unterdrückt oder massiv überbearbeitet

![[7c-_page_7_Figure_7.jpeg]]

### 7.17.2 Die Lösung: Modifizierte Gammafunktion

**Idee:** Verwende die reine Gammafunktion nur für **normale Helligkeitswerte**. Für sehr dunkle Werte nutze stattdessen eine **lineare Approximation**.

**Die modifizierte Gammafunktion sieht so aus:**

$$
f_{\text{mod}}(a) = \begin{cases}
c \cdot a & \text{für } a \leq a_{\text{linear}} \quad \text{(linearer Bereich)} \\
f_{\gamma}(a) & \text{für } a > a_{\text{linear}} \quad \text{(Gamma-Bereich)}
\end{cases}
$$

**Praktisch:**
- **Dunkle Pixel** (sehr niedrige Werte) werden **linear** transformiert — smooth ohne extreme Änderungen
- **Normale und helle Pixel** werden mit der **Gammafunktion** transformiert — wie gewohnt
- Der Übergang ist **stetig** — kein Sprung oder Kink in der Kurve

![[7c-_page_8_Figure_4.jpeg]]

**Visueller Vergleich:**
- **Gestrichelte Linie:** Pure Gammafunktion (problematisch bei Null)
- **Durchgezogene Linie:** Modifizierte Gammafunktion (gut bei Null)

## 7.18 **Punktoperationen mit mehreren Bildern**

### 7.18.1 Allgemeines Konzept

Bisher haben wir Punktoperationen angeschaut, die **ein einzelnes Bild** verarbeiten. Es ist aber auch möglich, **mehrere Bilder** an jeder Position zu kombinieren.

**Allgemeine Formel für $n$ Bilder:**

$$
I'(u,v) = f(I_1(u,v), I_2(u,v), \ldots, I_n(u,v))
$$

**Die Funktion $f$ kann beliebig komplex sein.**

### 7.18.2 Beispiel 1: Addition zweier Bilder

Das einfachste Beispiel — addiere zwei Bilder pixel-weise:

$$
I'(u,v) = I_1(u,v) + I_2(u,v)
$$

**Anwendung:** Rausch-Reduktion durch Mittelung mehrerer Aufnahmen

### 7.18.3 Beispiel 2: Alpha-Blending (Überblendung)

Eine wichtige Operation in der Bildbearbeitung — zwei Bilder mit verschiedenen Gewichtungen mischen:

$$
I'(u,v) = \alpha \cdot I_{\text{Background}}(u,v) + (1 - \alpha) \cdot I_{\text{Foreground}}(u,v)
$$

wobei $0 \leq \alpha \leq 1$ ein Transparenzwert ist.

**Praktische Beispiele:**
- **$\alpha = 1.0$:** Nur das Hintergrund-Bild sichtbar
- **$\alpha = 0.5$:** 50/50 Mischung (beide Bilder gleich sichtbar)
- **$\alpha = 0.0$:** Nur das Vordergrund-Bild sichtbar

## 7.19 **Effiziente Berechnung: Lookup-Tabellen**

### 7.19.1 Das Problem: Rechenzeit bei wiederholten Operationen

Bei der Verarbeitung großer Bilder (Millionen von Pixeln) kann die wiederholte Berechnung von $f(a)$ sehr langsam werden.

**Beispiel:**
- Bild mit 4000 × 3000 = 12 Millionen Pixeln
- Für jeden Pixel muss man $a^{\gamma}$ berechnen (eine teure Exponential-Operation)
- Das kann Sekunden bis Minuten dauern

### 7.19.2 Die Lösung: Lookup-Tabellen (LUT)

Eine **Lookup-Tabelle** ist ein großes **Array**, das vorberechnet wird:

$$
\text{LUT}[a] = f(a) \quad \text{für alle } a \in [0, 255]
$$

**Wie es funktioniert:**

1. **Vorberechnung (einmalig):**
   - Berechne $f(0), f(1), f(2), \ldots, f(255)$ und speichere in Array LUT

2. **Anwendung (schnell):**
   - Für jeden Pixel mit Wert $a$ einfach `LUT[a]` nachschlagen
   - Das ist ein einfacher Array-Zugriff — extrem schnell!

### 7.19.3 Praktisches Beispiel: Invertierung mit Lookup-Tabelle

**Invertierungs-Funktion:** $f(a) = 255 - a$

**Vorberechnung der Lookup-Tabelle:**

| Index a | Wert LUT[a] |
|---------|------------|
| 0 | 255 |
| 1 | 254 |
| 2 | 253 |
| ... | ... |
| 254 | 1 |
| 255 | 0 |

**Im Programmcode:**

```java
// Schritt 1: Lookup-Tabelle aufbauen (nur einmal)
int[] lut = new int[256];
for (int a = 0; a < 256; a++) {
    lut[a] = 255 - a;  // Invertierung
}

// Schritt 2: Auf das Bild anwenden (schnell)
for (int v = 0; v < height; v++) {
    for (int u = 0; u < width; u++) {
        int oldValue = image.getPixel(u, v);
        int newValue = lut[oldValue];  // Schneller Zugriff!
        image.setPixel(u, v, newValue);
    }
}
```

### 7.19.4 Vorteile und Nachteile

| Aspekt | Lookup-Tabelle | Direkte Berechnung |
|--------|----------|-----------|
| **Geschwindigkeit** | Sehr schnell | Kann langsam sein |
| **Speicher** | 256-1024 Bytes | Keine extra |
| **Genauigkeit** | Diskret (nur 256 Werte) | Potentiell höher |
| **Flexibilität** | Muss neu berechnet werden | Einfach zu ändern |

> [!tip] Best Practice
> **Nutze Lookup-Tabellen für:**
> - Teure Operationen (Potenzen, Trigonometrie)
> - Häufig wiederholte Operationen
> - Bei Bildern mit Millionen von Pixeln
>
> **Nutze direkte Berechnung für:**
> - Schnelle, einfache Operationen
> - Wenn der Algorithmus sich häufig ändert
> - Bei kleinen oder mittelgroßen Bildern

> - Lösung: Modifizierte Gammafunktion mit linearem Anteil
>
> **Mehrbilder-Operationen:**
> - $I' = f(I_1, I_2, \ldots, I_n)$
> - Addition: $I' = I_1 + I_2$
> - Alpha-Blending: $I' = \alpha \cdot I_{\text{BG}} + (1-\alpha) \cdot I_{\text{FG}}$
>
> **Lookup-Tabellen:**
> - Vorberechnung: $\text{LUT}[a] = f(a)$ für alle $a \in [0, 255]$
> - Anwendung: Schneller Array-Zugriff statt wiederholter Berechnung
> - Ideal für teure Operationen bei großen Bildern
