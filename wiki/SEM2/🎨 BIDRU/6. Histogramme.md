# 6. Histogramme

## 6.1 Bilder als diskrete Funktionen

### 6.1.1 Diskrete Funktion $F(x,y)$

![[6-page_1_Picture_1.jpeg|395x513]]
**Visuelle Ansicht:** Das Foto zeigt, wie wir das Bild wahrnehmen. Jeder Punkt hat eine Helligkeit, die mathematisch als $F(x,y)$ beschrieben wird.

$F(x,y)$ beschreibt die Grauwertmatrix eines Bildes:

![[Pasted image 20260518135418.png]]
**Computer-Ansicht (Matrix):** Für den Computer ist das Bild eine Tabelle (Matrix) aus Zahlen. Jeder Wert (z.B. 148, 52) repräsentiert die Intensität $I(u,v)$ eines Pixels. Bei 8-Bit-Bildern gilt: 0 = Schwarz, 255 = Weiß.

$I(u,v)$ — Intensität am Pixel an der Position $(u,v)$
- **$u$:** Spaltenindex (horizontale Position)
- **$v$:** Zeilenindex (vertikale Position)

### 6.1.2 Kontinuierliches Bildmodell

![[6-page_2_Figure_1.jpeg|498|700x415]]
**Das Bildkoordinatensystem:** Ein digitales Bild wird als Raster (Matrix) mit $M$ Spalten und $N$ Zeilen dargestellt. Der Ursprung (0,0) liegt oben links. Die Indizes laufen von $0$ bis $M-1$ (Breite) bzw. $N-1$ (Höhe). Da wir einzelne Pixel haben, sind $u$ und $v$ ganze Zahlen

Das Symbol **$\mathbb{P}$** (Bildwerte) steht für den gesamten Bereich der möglichen Helligkeitsstufen (z.B. 0 bis 255).

## 6.2 Histogrammfunktion

Ein Histogramm zeigt, wie oft welche Helligkeit im Bild vorkommt (Häufigkeitsverteilung).
- **Grauwertbild:** Nutzt Werte von $0$ (Schwarz) bis $K-1$ (Weiß).
- **Einträge ($K$):** Meist gibt es 256 Stufen ($K=256$).
- **Berechnung:** $h(i)$ ist die Anzahl der Pixel, die genau die Helligkeit $i$ haben.
  - Histogramm-Eintrag: $h(i) = \text{card}\{(u,v) \mid I(u,v) = i\}$
  - Pixelzahl mit Intensitätswert $i$; $0 \leq i < K$

![[6-page_3_Figure_6.jpeg|672x238]]
**Beispiel für ein Histogramm ($K=16$):** Das Diagramm zeigt die Verteilung von 16 möglichen Graustufen (0 bis 15). Der Balken bei $i=2$ zeigt beispielsweise, dass es im Bild 10 Pixel mit diesem Helligkeitswert gibt. Die Tabelle darunter verdeutlicht, wie diese Daten als Liste (Array) im Computer gespeichert werden: Für jeden Wert $i$ wird die Anzahl der Pixel $h(i)$ notiert.

### 6.2.1 Histogramm berechnen

```java
// Annahme: Bild mit 256 Graustufen
// Diese Funktion gibt das Histogramm des Bildes als Feld zurück
int[] histogram(Image image) {
    int[] H = new int[256]; // Erstelle Histogramm-Feld mit 256 Zellen
    int w = image.getWidth(); // Ermittle Bildbreite
    int h = image.getHeight(); // Ermittle Bildhöhe
    // Durchlaufe alle Pixelpositionen (u,v) des Bildes
    for (int v = 0; v < h; v++) {
        for (int u = 0; u < w; u++) {
            int i = image.getFixed(u,v); // Hole Pixelgrauwert i an der Position (u,v)
            H[i] = H[i] + 1; // Erhöhe den Zähler für den Wert i im Histogramm
        }
    }
    return H; // Gib Histogramm-Feld zurück
}
```

## 6.3 Histogrammeigenschaften

>Die Zuordnung Intensitätswert $\leftrightarrow$ Pixelort geht im Histogramm verloren.

![[6-page_6_Figure_2.jpeg]]
**Alle Bilder haben das gleiche Histogramm** — aber völlig unterschiedlicher Inhalt.

### 6.3.1 Lineare und Logarithmische Darstellung

![[6-page_7_Figure_1.jpeg]]

**Linear vs. Logarithmisch:** 
- **Linear (schwarz):** Zeigt die echte Pixelanzahl. Große "Berge" dominieren die Ansicht, kleine Werte gehen optisch unter.
- **Logarithmisch (grau):** Staucht große Unterschiede zusammen. Dadurch werden auch Helligkeitswerte sichtbar, die nur sehr selten im Bild vorkommen ("Gute Sichtbarkeit kleiner Werte").
- **Kontrastumfang:** Der Bereich zwischen dem dunkelsten ($a_{\text{low}}$) und hellsten ($a_{\text{high}}$) Pixelwert im Bild.

### 6.3.2 Belichtungsfehler

![[6-page_8_Picture_4.jpeg|700x334]]

**Belichtungssituationen erkennen:**
- **Unterbelichtung (a):** Das Histogramm ist nach links verschoben. Die hellen Tonwerte fehlen fast völlig.
- **Korrekte Belichtung (b):** Die Tonwerte sind gleichmäßig über den Bereich verteilt (ideale Ausnutzung).
- **Überbelichtung (c):** Das Histogramm ist nach rechts verschoben. Die Spitze ganz rechts zeigt die **Sättigung** an: Viele Pixel sind reinweiß, wodurch Details in hellen Flächen verloren gehen.

### 6.3.3 Kontrast und Kontrastumfang

Der Kontrast beschreibt die Spannweite und Verteilung der Helligkeitswerte. Im Histogramm erkennt man dies an der Breite der genutzten Fläche.

- **Geringer Kontrast (a):** Die Pixelwerte liegen nah beieinander (schmaler "Berg"). Es gibt kein echtes Schwarz und kein echtes Weiß, das Bild wirkt "flau" oder grau.
- **Normaler/Optimaler Kontrast (b):** Die Tonwerte nutzen den gesamten Bereich ($0$ bis $K-1$) gleichmäßig aus. Details sind in allen Helligkeitsstufen gut erkennbar.
- **Hoher Kontrast (c):** Die Werte liegen weit auseinander, oft mit Peaks an den Rändern und Lücken in den Graustufen. Das Bild wirkt "hart" mit starken Unterschieden zwischen Hell und Dunkel.

![[6-page_9_Picture_4.jpeg]]
**Kontrastumfang:** Der Bereich zwischen dem dunkelsten ($a_{\text{low}}$) und hellsten ($a_{\text{high}}$) Pixelwert. Ein breites Histogramm bedeutet einen hohen Kontrastumfang.

### 6.3.4 Dynamik

Die Dynamik bezeichnet die **Anzahl der tatsächlich verwendeten, unterschiedlichen Helligkeitswerte** im Bild. Während der Kontrast die *Breite* beschreibt, beschreibt die Dynamik die *Feinheit* der Abstufungen.

- **Hohe Dynamik (a):** Das Bild nutzt fast alle verfügbaren Stufen (z.B. 256 bei 8-Bit). Verläufe wirken weich und natürlich.
- **Niedrige Dynamik (b):** Es werden deutlich weniger Werte genutzt (z.B. nur 64 Stufen). Das Histogramm bekommt Lücken ("Kamm-Effekt").
- **Sehr niedrige Dynamik (c):** Nur extrem wenige Werte (z.B. 6 Stufen). In eigentlich glatten Verläufen (wie dem Himmel) entstehen harte Kanten (**Posterisation** oder **Banding**).

> [!tip] Merke
> Eine hohe Dynamik bei der Aufnahme ist die wichtigste Reserve für die Bildbearbeitung. Wenn man ein Bild mit niedriger Dynamik später im Kontrast spreizt, werden die Lücken im Histogramm noch größer und Bildfehler sichtbar.

![[6-page_10_Figure_5.jpeg]]

### 6.3.5 Sättigung

Sättigung tritt auf, wenn die Helligkeitsunterschiede der Umgebung größer sind, als der Kamerasensor erfassen kann. Die Information "läuft über" und sammelt sich an den Rändern.

- **Sättigung am Rand (a):** Wenn zu viele Pixel den Maximalwert (255) oder Minimalwert (0) erreichen, entstehen steile Spitzen ganz rechts oder links im Histogramm. In diesen Flächen gibt es keine Zeichnung (Details) mehr – sie sind einfach reinweiß oder tiefschwarz (**Clipping**).
- **Löcher durch Kontrasterhöhung (b):** Wenn man ein kontrastarmes Bild digital "streckt", um den Bereich besser auszunutzen, werden die vorhandenen Grauwerte auseinandergezogen. Da keine neuen Zwischenwerte erfunden werden können, entstehen Lücken (leere Bins) im Histogramm.
- **Spitzen durch Kontrastreduktion (c):** Wenn man den Kontrast verringert (das Histogramm zusammenstaucht), werden mehrere benachbarte Helligkeitswerte auf einen einzigen Wert zusammengefasst. Dadurch entstehen künstliche Spitzen im Histogramm.

![[6-page_11_Figure_5.jpeg]]

## 6.4 Binning — Histogramme für große Wertebereiche

### 6.4.1 Warum Binning? (Das Problem)

Normale Histogramme haben für jeden Helligkeitswert eine eigene Spalte. Bei **16-Bit-Bildern** (z.B. aus Profi-Kameras oder medizinischen Scannern) gibt es $65.536$ mögliche Graustufen ($K=2^{16}$).
- Ein Monitor hat oft nur 1920 Pixel Breite – man kann unmöglich jede Stufe als einzelnen Balken darstellen.
- Das Histogramm wäre viel zu detailliert ("Rauschen") und unübersichtlich.

**Lösung:** Man fasst benachbarte Helligkeitswerte zu Gruppen (**Bins** = "Eimer" oder "Klassen") zusammen.

### 6.4.2 Logik und Berechnung

Statt jede einzelne Graustufe anzuzeigen, fassen wir benachbarte Werte in Gruppen zusammen.

**Erklärung der Variablen:**
- **$K$**: Gesamtzahl aller möglichen Graustufen (z. B. 256 bei 8-Bit).
- **$B$**: Anzahl der gewünschten „Bins“ (Balken) im Histogramm.
- **$k_B$**: Die Breite eines einzelnen Bins (Intervalllänge).
- **$j$**: Der Index (die Nummer) eines Bins, von $0$ bis $B-1$.
- **$a_j$**: Der Helligkeits-Startwert, ab dem ein Bin beginnt.

**Der Rechenweg:**

1. **Intervalllänge berechnen:**
   $$k_B = \frac{K}{B}$$

2. **Startwert eines Bins $j$ bestimmen:**
   $$a_j = j \cdot k_B$$

3. **Bin-Index $j$ aus einem Pixelwert $I(u,v)$ ermitteln:**
   $$j = \left\lfloor \frac{I(u,v)}{k_B} \right\rfloor = \left\lfloor \frac{I(u,v) \cdot B}{K} \right\rfloor$$
   *Das ist die "Einsortier-Regel": Man teilt die Helligkeit des Pixels durch die Breite eines Bins. Das Ergebnis sagt dir, in welchen "Eimer" der Pixel geworfen wird (z. B. Pixelwert 157 bei Bin-Breite 64 $\rightarrow$ $157/64 \approx 2,45 \rightarrow$ abgerundet landet er in Bin 2).*

4. **Bin-Inhalt $h(j)$ füllen (Mächtigkeit der Menge):**
   $$h(j) = \text{card} \{(u, v) \mid a_j \leq I(u, v) < a_{j+1}\} \quad \text{für } 0 \leq j < B$$
   *Das ist die "Zähl-Regel": $h(j)$ ist einfach die Anzahl (card = Cardinality/Mächtigkeit) aller Pixel, deren Helligkeit genau in den Bereich von Bin $j$ passt.*


### 6.4.3 Rechenbeispiel

Stellen wir uns ein Bild mit hoher Farbtiefe vor, das wir für ein Standard-Histogramm reduzieren wollen.

- **Ausgangslage:** Ein 14-Bit Bild hat $K = 16.384$ Graustufen (Werte von 0 bis 16.383).
- **Ziel:** Wir wollen ein übersichtliches Histogramm mit $B = 256$ Bins (Balken).

**1. Schritt: Bin-Breite berechnen**
$$k_B = \frac{16.384}{256} = 64$$
Jeder Balken im Histogramm repräsentiert also genau 64 aufeinanderfolgende Helligkeitswerte.

**2. Schritt: Einordnung eines Pixels (Beispiel)**
Ein Pixel an Position $(u,v)$ hat den Helligkeitswert **$120$**. In welchen Bin $j$ gehört er?
$$j = \left\lfloor \frac{120}{64} \right\rfloor = \lfloor 1,875 \rfloor = \mathbf{1}$$
Der Pixel landet also in **Bin 1**.

**Übersicht der Bins:**
- **Bin 0:** Enthält alle Pixel mit Werten von $[0, 64)$ (also 0 bis 63).
- **Bin 1:** Enthält alle Pixel mit Werten von $[64, 128)$ (also 64 bis 127).
- **Bin 2:** Enthält alle Pixel mit Werten von $[128, 192)$ (also 128 bis 191).
- ...
- **Bin 255:** Enthält die hellsten Pixel von $[16320, 16384)$.

### 6.4.4 Programmbeispiel Binning

Die Formel `j = a * B / K` sorgt im Code dafür, dass jeder Pixelwert sofort in seinem richtigen "Eimer" landet:

```java
int[] binnedHistogram(Image im) {
    int K = 256; // Hier im Beispiel 8-Bit, bei 16-Bit wäre K = 65536
    int B = 32;  // Wir wollen das Histogramm auf 32 Bins reduzieren
    int[] H = new int[B];
    
    int w = im.getWidth();
    int h = im.getHeight();

    for (int v = 0; v < h; v++) {
        for (int u = 0; u < w; u++) {
            int a = im.getFixed(u, v); // Originalwert (0 bis K-1)
            
            // Umrechnung auf Bin-Index (0 bis B-1):
            // Durch die Ganzzahl-Division wird automatisch abgerundet.
            int j = (a * B) / K; 
            
            H[j] = H[j] + 1;
        }
    }
    return H;
}
```

## 6.6 Kumulatives Histogramm und Normalisierung

### 6.6.1 Kumulatives Histogramm (Summenhistogramm)

$H(i)$: Summe der Häufigkeiten der Intensitätswerte $0$ bis $i$ (bezogen auf ein Bild). Monoton steigende Funktion.

$$
H(i) = \sum_{j=0}^{i} h(j) \quad \text{für } 0 \leq i < K
$$

- $H_{\text{max}}$: Gesamtzahl der Pixel eines Bildes mit der Breite $M$ und Höhe $N$

$$
H(K-1) = \sum_{j=0}^{K-1} h(j) = M \cdot N
$$

![[6-page_20_Picture_1.jpeg]]

![[6-page_20_Figure_2.jpeg]]

### 6.6.2 Normalisierte Histogramme

Normalisiertes Histogramm enthält relative Häufigkeiten:

$$
p(i) = \frac{h(i)}{M \cdot N}
$$

$M$ ... Bildbreite in Pixeln, $N$ ... Bildhöhe in Pixeln

$$
\sum_{i=0}^{K-1} p(i) = 1
$$

> [!question] Warum kann es sinnvoll sein, Histogramme zu normalisieren?
> - Vergleichbarkeit zwischen Bildern unterschiedlicher Größe
> - Wahrscheinlichkeitsinterpretation

### 6.6.3 Verteilungsfunktion

Pendant zum kumulativen Histogramm $H$: Kumulierte Wahrscheinlichkeitsdichte (nachfolgend kurz Verteilungsfunktion):

$$
P(i) = \frac{H(i)}{M \cdot N}
$$

$P(i)$ monoton steigend, es gilt:

$$
P(0) = p(0)
$$
und $P(K-1) = \sum_{i=0}^{K-1} p(i) = 1$

> Gegeben ist ein 3×3-Bild mit Graustufen 0–3 (2 Bit/Pixel; 0=schwarz, 3=weiß):

> | 0 | 0 | 1 |
> |---|---|---|
> | 0 | 2 | 3 |
> | 0 | 3 | 2 |
>
> Skizzieren Sie a) das Histogramm, b) das kumulative Histogramm, c) das „Binned" Histogramm der Größe 2.

>

>
> | $i$ | 0 | 1 | 2 | 3 |

> | $h(i)$ | 4 | 1 | 2 | 2 |

>
> | $i$ | 0 | 1 | 2 | 3 |

> | Bin | Werte | Anzahl |
