### 1.1.4 Rechnernetzanwendungen

> [!abstract] Definition: Rechnernetz
> Mehrere gekoppelte autonome Rechner mit diversen Architekturen. Kopplung über elektrische Leitung, Lichtwellenleiter, Rundfunk, Richtfunk oder Satellitenfunk.

![[1-ecommerce-b2c-b2b.jpeg]]

Beispiel E-Commerce: Das Frontend (B2C) verbindet Clients (Smartphone, Tablet, PC) über einen Web Server mit den Application Servern des Online Shops (Purchase Order Preprocessing, Store Management, Customer Data Maintenance) und deren Datenbanken (Store Tables, Customer Data). Das Backend (B2B) bindet per Web Service den Lieferanten (Supplier) mit Goods Management und Goods-Datenbank an. Als Netze dienen z.B. DSL, WLAN, 4G.

**B2B** = Business-to-Business, **B2C** = Business-to-Consumer

### 1.1.5 Architekturen

**Client-Server (C-S), n-tier**

![[1-architektur-client-server-tiers.jpeg]]

- Presentation Tier (Client): Benutzerschnittstelle, ggf. Vorverarbeitung (Kasse/Point-of-Sale, Geldautomat/Mitarbeiter im Außendienst, Heimzugang)
- Processing Tier (Server): Anwendungslogik (z.B. Kontenserver)
- Persistence Tier (Server): Datenverwaltung für Nutzer- und Anwendungsdaten (z.B. [[1. Einführung in Datenbanken|Datenbank]])

**Mehrstufige Architektur:**

- **3-tier:** dreistufige Struktur; bei komplexen Anwendungen zu bevorzugen
- **2-tier:** zweistufige Struktur (Benutzerschnittstelle – Host); einfacher, aber weniger flexibel

**Clustering**

![[1-architektur-clustering.jpeg]]

Die Anwendungslogik läuft auf einem Cluster von Servern. Eine Warteschlange/MPI (Message Passing Interface) verteilt die Anfragen der Clients auf die Server. Die Nutzer- und Anwendungsdaten liegen auf RAID, SAN, NAS.

**Clouds**

![[1-architektur-clouds.jpeg]]

Thin Clients greifen über Internet/Intranet/Web Services auf Private/Public Clouds zu. Dort liegen der Server-Cluster (Anwendungslogik) und die Speicher (RAID, SAN, NAS) für Nutzer- und Anwendungsdaten.

### 1.2.2 Rechnernetz-Strukturen

![[1-rechnernetz-grundstruktur.jpeg]]

Ein (Teil-)Netz besteht aus Kanälen und Vermittlungsstellen (z.B. Paketweiterleitung gemäß Adressen). An die Vermittlungsstellen sind Terminals, Rechner und Endgeräte angeschlossen.

**Übertragungsmodi:**

1. **Verbindungsorientiert:** feste Beziehung Sender ⇒ Empfänger (z.B. Telefon)
2. **Verbindungslos:** keine solche feste Beziehung (z.B. Briefpost, Internet Protocol)
3. **Leitungsvermittelt:** exklusive Durchschaltung einer (ggf. virtuellen) Leitung für die Dauer der Kommunikation ⇒ feste Dienstqualität; in der Regel verbindungsorientiert
4. **Paketvermittelt:** gemeinsame Nutzung eines Übertragungskanals für unabhängig vermittelte Pakete verschiedener Teilnehmer ⇒ flexibler, ressourcenschonend; kann sowohl verbindungslos als auch verbindungsorientiert realisiert werden

![[1-integration-per-ip.jpeg]]

Netzwerktypen (Wireless, Wired, Mobile) und Dienste (Voice, IP, Multimedia) wachsen zusammen: Integration per IP.

**Punkt-zu-Punkt-Kanäle:** z.B. Weitverkehrsnetze (WAN = Wide Area Network)

![[1-punkt-zu-punkt-topologien.jpeg]]

Topologien: Stern, Baum, Irregulär

**Rundsendekanäle:** z.B. Lokale Netze (LAN = Local Area Network); Broadcast / Multicast; dezentral

![[1-rundsende-topologien.jpeg]]

Topologien: Bus (z.B. Ethernet), Ring (z.B. Token Ring), Satellit (z.B. Inmarsat)

### 1.2.3 Netzwerk-Architekturen

> [!warning] Problem: hohe Komplexität. Lösung: Schichtenstruktur, Abstraktion, Entkopplung.

**ISO/OSI-Referenzmodell:** International Standardization Organisation / Open System Interconnection

![[1-osi-protokolle-dienste.jpeg]]

Jede Schicht (1 Bitübertragung, 2 Sicherung, 3 Vermittlung, 4 Transport, 5 Sitzung, 6 Darstellung, 7 Anwendung) kommuniziert mit der gleichen Schicht des Partners über ein eigenes Protokoll. Zwischenstationen (Vermittlungsstellen) betreiben nur die Schichten 1 bis 3.

> [!abstract] Definition: Protokoll
> Regeln zur Steuerung der Kommunikation pro Schicht.

> [!abstract] Definition: Dienst
> Durch ein Protokoll erbrachte Funktionalität (z.B. Austausch von E-Mail).

| Schicht | Protokolltyp | Beispiel |
| --- | --- | --- |
| 7 Anwendung | Anwendungsprotokoll | |
| 6 Darstellung | Darstellungsprotokoll | |
| 5 Sitzung | Sitzungsprotokoll | |
| 4 Transport | Transportprotokoll | TCP |
| 3 Vermittlung | Vermittlungsprotokoll | IP |
| 2 Sicherung | Sicherungsprotokoll | HDLC (High Level Data Link Control) |
| 1 Bitübertragung | Bitübertragungsprotokoll | |


### 1.2.4 Schichtenfunktionalität

**1. Bitübertragungsschicht**

- Umsetzung in elektrische Signale (z.B. "0" = 1 Volt)
- Mechanische und elektrische Kopplung

**2. Sicherungsschicht**

- Behandlung von Übertragungsfehlern
- Überlastungsvermeidung (Flusssteuerung)

**3. Vermittlungsschicht**

- Wegewahl Sender ⇒ Empfänger (statisch / dynamisch)
- Kopplung heterogener Teilnetze (Anpassung, Abrechnung)

**4. Transportschicht**

- Sichere Ende-zu-Ende-Kommunikation zwischen Prozessen
- Multiplex, Bündelung, Flusssteuerung

**5. Sitzungsschicht (Kommunikationssteuerung)**

- Dialogsteuerung (simplex / duplex / halbduplex)
- Synchronisation (Sicherungspunkte)

**6. Darstellungsschicht**

- Transformation zwischen Datenformaten (z.B. ASCII ⇒ EBCDIC)
- Kompression, Verschlüsselung

**7. Anwendungsschicht**

- Kommunikation zwischen Anwendungen, spezielle Dienste (z.B. Remote Procedure Call, FTP, E-Mail, Telnet, WWW etc.)

> [!tip] Merke: Das OSI-Modell ist ein Referenzmodell, kein Implementierungsmodell.
> Die unteren 4 Schichten (übertragungsorientiert) werden teilweise in Hardware umgesetzt (z.B. Ethernet-Karte mit Schicht 1 und 2) und teilweise in Software (z.B. TCP/IP mit Schicht 3 und 4). Die oberen Schichten sind meist in Software integriert.

### 1.2.5 Schichtenschnittstelle und Terminologie

![[1-schichtenschnittstelle-idu-sdu.jpeg]]

- **IDU:** Interface Data Unit
- **ICI:** Interface Control Information
- **SDU:** Service Data Unit
- **PDU:** Protocol Data Unit
- **SAP:** Service Access Point

Die Schicht N+1 übergibt über den SAP an der Schnittstelle eine IDU (ICI + SDU) an Schicht N. Schicht N verpackt die SDU in eine N-PDU.

![[1-schichtenarchitektur-terminologie.jpeg]]

- Die verarbeitungsorientierten Schichten (Anwendung, Darstellung, Sitzung) werden integriert betrachtet.
- Die übertragungsorientierten Schichten (Transport, Vermittlung, Sicherung, Bitübertragung) werden einzeln betrachtet.
- **Instanz:** Element einer Schicht (z.B. Software-Modul)
- **Dienstzugangspunkt (SAP = Service Access Point):** Schnittstelle einer Schicht mit Adresse

### 1.2.6 Beispiel zur Übertragung im OSI-Modell

### 1.2.9 Novell-Architektur

![[1-novell-architektur.jpeg]]

Implementierungsarchitektur, proprietär:

- In den 80er Jahren entstanden die ersten LANs, die meist einen Verbund sehr ressourcenschwacher PCs (Clients) mit einem leistungsstärkeren Rechner (Server) realisierten.
- Zugriff auf das Netz über einen LAN-spezifischen Treiber mit standardisierter Treiberschnittstelle.
- Darüber existieren zwei Schichten, welche die Protokolle IPX (Internetworking Packet Exchange) und SPX (Sequenced Packet Exchange) realisieren.
  - IPX realisiert die Nachrichtenübertragung vom Quell- zum Zielrechner, wobei unter Umständen mehrere Zwischenrechner passiert werden müssen.
  - SPX steuert die Nachrichtenübertragung und korrigiert IPX-Fehler.
  - Auf diesen Schichten baut das Netzwerkbetriebssystem Novell NetWare auf.
- Die wichtigsten Anwendungsdienste von Novell-NetWare-Netzen waren der Zugriff der Clients auf das Dateisystem des Fileservers und ein Druckservice für die Clients.

## 1.3 Bitübertragungsschicht

### 1.3.1 Nachrichtentechnische Kanäle

**Aufgabe:** physikalische Bitübertragung mittels Transformation in ein elektrisches / optisches Signal

![[1-kanal-signal-stoerung.jpeg]]

Das Signal im Kanal wird durch Störeinflüsse (Rauschen, Echo etc.) verändert.

- **Baudrate:** Anzahl Signalschritte/s [Baud] ("Schrittgeschwindigkeit")
- **Bitrate $b$:** Anzahl übertragener Bits/s [bit/s] ("Datenrate")
- **Bandbreite des Kanals $B$** (bzw. durch die BNetzA festgelegt)

![[1-bandbreite-kanal.jpeg]]

Bitrate $b$ = Datenrate der Schicht 1 = $DR_1$. Die Bandbreite des Kanals ist $B = f_o - f_u$ (obere minus untere Grenzfrequenz).

Bei $S$ Signalstufen gilt:

$$b = \text{Baudrate} \cdot \text{Anzahl Bits/Signaländerung} \quad (= \text{ld } S)$$

![[1-signalstufen-nyquist-shannon.jpeg]]

Beispiel: $S = 4 \Rightarrow b = 2 \cdot \text{Baudrate}$ [bit/s]

> [!abstract] Definition: Nyquist-Shannon-Theoreme (ca. 1948)
> **Theorem I** (Bandbreite des Kanals $B$ in Hz):
> $$b < 2B \cdot \text{ld } S \quad [\text{bit/s}]$$
> - $B = 3$ kHz, $S = 2$ (binär) $\Rightarrow b < 6000$ bit/s
> - $B = 5$ MHz, $S = 512$, $\text{ld } S = 9$ Bit $\Rightarrow b = 90$ Mbit/s
>
> **Theorem II** (Signal-Rauschabstand):
> $$b < B \cdot \text{ld}(1 + SNR) \quad [\text{bit/s}]$$
> - $SNR$ = Signalleistung / Rauschleistung = [W] / [W]
> - Angabe oft logarithmisch: $SNR_{dB} = 10 \cdot \lg SNR$ [in dB]
> - $B = 3$ kHz, $SNR = 7 \Rightarrow b < 9000$ bit/s, unabhängig davon, wie viele Signalstufen benutzt werden
> - $B = 5$ MHz, $SNR = 2047$, $\text{ld}(1 + SNR) = 11$ Bit $\Rightarrow b$ nur 55 Mbit/s, nicht 90 Mbit/s. $SNR_{dB}(2047) = 10 \cdot \lg 2047 = 33$ dB
>
> **Folge aus N-I/II:** $b \approx B/3 \cdot SNR_{dB}$, z.B. $(5\text{ MHz}/3) \cdot 33\text{ dB} \approx 55$ Mbit/s

> [!tip] Merke: Die tatsächliche Bitrate wird von beiden Grenzen bestimmt:
> $$b = DR_1 < \min\left(2B \cdot \text{ld } S,\; B \cdot \text{ld}(1 + SNR)\right) \quad [\text{bit/s}]$$

**Übung Ü2 A5:** Nyquist-Theorem mit $S = 4$, $\text{ld } S = 2$ Bit: $DR < 4B$, d.h. 4x Bandbreite $B$ [Hz]. Datenrate im rauschfreien Kanal: $DR = 2B \cdot \text{ld } S$ [bit/s].

![[1-zeitdiagramm-uebung-ue2a5.jpeg]]

Handschriftliche Lösung für $DR = 96$ Mbit/s und $\text{ld } S = 8$ Bit:

$$DR = 2B \cdot \text{ld } S \Rightarrow B = \frac{DR}{2 \cdot \text{ld } S} = \frac{96 \text{ Mbit/s}}{2 \cdot 8 \text{ Bit}} = 6 \text{ MHz}$$

$$DR = B \cdot \text{ld}(1 + SNR) \Rightarrow B = \frac{DR}{\text{ld}(1 + SNR)} = \frac{96 \text{ Mbit/s}}{\text{ld}(1 + 63) \text{ Bit}} = \frac{96 \text{ Mbit/s}}{6 \text{ Bit}} = 16 \text{ MHz}$$

### 1.3.3 Übertragungsmedien

**Elektrische Leitungen:**

- **Verdrillte Adern (Twisted Pair):** 1 mm Stärke, Reduzierung von Störungen durch schraubenförmiges Umeinanderwickeln der Fasern (Verdrillung)
  - mehrere 100 m, mehrere MBit/s, preiswert
  - Cat 3: Telefonkabel
  - Cat 5-7: Datenkabel
  - Grenzfrequenz ca. 700 MHz, Cat 7A (1 GHz)
  - In Entwicklung: Cat 8 (1,6-2 GHz)

![[1-twisted-pair-kabel.jpeg]]

- **Koaxialkabel:** Aufbau aus Kupfer, Isolierung, Außenleiter und Schutzschicht
  - Entfernung: ~km, mehrere MBit/s; T-Stecker oder Tap
  - Grenzfrequenz bis max. 900 MHz

![[1-koaxialkabel-aufbau.jpeg]]

- **Kabelfernsehen:** Breitband-Koaxialkabel, häufig mit analoger Übertragung bis ca. 1 GHz; vom Kopfende über Verstärker zu den Teilnehmern. Ausbau für Internet-Zugang via Kabel.

![[1-kabelfernsehen-verstaerker.jpeg]]

**Optische Leitungen:** Lichtwellenleiter / Glasfaser: bis in den Tbit/s-Bereich, über viele km Entfernung

- **Monomodefaser:** nur eine ausbreitungsfähige Wellenform (leistungsfähiger, mit Laserdiode, aber teurer)
- **Multimodefaser:** verschiedene ausbreitungsfähige Wellenformen
- **Gradientenfaser:** schrittweise Änderung des Brechungsindex

![[1-glasfaser-totalreflexion.jpeg]]

Eine LED oder Laserdiode sendet Licht (ca. $3 \cdot 10^8$ MHz), das per Totalreflexion in der Faser geführt und von einer Photodiode empfangen wird.

**Sichtverbindung:**

- Laserlinks, Infrarotverbindungen (Grenzfrequenz bei ca. 10 THz)

- Zuordnung kurzer Zeitabschnitte zu einzelnen Kanälen (Zeitmultiplex TDM)
- Häufig lange Laufzeiten (ca. 0,24 s) bei GEO

### 1.3.4 Mehrfachnutzung von Kanälen

**Ziel:** leistungsfähige Kanäle auf mehrere Nutzer aufteilen, z.B. bei DSL, ISDN etc.

![[1-multiplexverfahren.jpeg]]

- **Frequenzmultiplex (FDM, Frequency Division Multiplexing):** getrennte Frequenzbänder (mit z.B. 3000 Hz) und zwischengeschaltete Sperrbänder (mit z.B. 500 Hz)
- **Zeitmultiplex (TDM, Time Division Multiplexing):** zyklische Kanalzuteilung
- **Statistisches Zeitmultiplex:** Zuteilung nach Bedarf; flexibler

In der Praxis wird oft eine Kombination von Frequenz- und Zeitmultiplex (FDM+TDM) eingesetzt.

### 1.3.5 Signalklassen

![[1-signalklassen.jpeg]]

Signale lassen sich nach Wert (kontinuierlich / diskret) und Zeit (kontinuierlich / diskret) einteilen. Das Eingangssignal ist wert- und zeitkontinuierlich, nach der Abtastung zeitdiskret und nach der Quantisierung zusätzlich wertdiskret.

**Vorteile der digitalen Übertragung:**

- Speicherbarkeit
- Gute Regenerierbarkeit
- Zeitmultiplex nutzbar
- Störsicherheit
- Verschlüsselbarkeit

**Beispiele:**

- Wert- und zeitkontinuierlich: analoges Telefon
- Wertkontinuierlich, zeitdiskret: Prozesssteuerung mit periodischen Messpunkten
- Wertdiskret, zeitkontinuierlich: digitaler Tachometer mit beliebigen Signalwechseln
- Wert- und zeitdiskret: digitale Übertragung mit isochronem Taktmuster (Taktrate konstant), z.B. Sprachübertragung über digitale Kanäle

### 1.3.6 Sprachübertragung über digitale Kanäle

Analoge Eingangssignale (Sprache) müssen vor der Übertragung im Kernnetz digitalisiert werden: **Codec** (Coder-Decoder).

> [!abstract] Definition: Abtasttheorem nach Shannon
> Die Abtastfrequenz muss höher als die doppelte Grenzfrequenz des Signals sein: $f_A > 2 \cdot f_{Grenz}$

![[1-abtastung.jpeg]]

**PCM: Pulse Code Modulation**

Beispiel Telefon:

- Grenzfrequenz: 3400 Hz
- Abtastfrequenz: 8000 Hz
- Anschließende Quantisierung mit 256 Intervallen ⇒ 8 bit pro Signalwert ⇒ 64 kbit/s
- Logarithmische Quantisierungsintervalle ⇒ Quantisierungsfehler begrenzen
- Kompression durch differentielle PCM bzw. Delta-Modulation

### 1.3.8 Datenübertragung über analoge Kanäle

**Modem:** Übertragung digitaler Signale über eine analoge Telefonverbindung

> [!warning] Problem: Direkt nicht möglich wegen kapazitiver und induktiver Einflüsse.

Lösung: Modulation / Tastung auf einem Sinusträger (z.B. 1000-2000 Hz bei Telefonie); Bitrate bis ca. 56 kbit/s.

$$s(t) = A \cdot \sin(\omega t + \varphi_0)$$

Die drei Parameter Amplitude $A$, Frequenz $\omega$ und Phase $\varphi_0$ können moduliert werden:

| Verfahren | Codierung der "0" |
| --- | --- |
| Amplitudentastung | niedrige Amplitude |
| Frequenztastung | niedrige Frequenz |
| Phasentastung (am störsichersten) | Phasensprung, z.B. um 180° |

### 1.3.10 Digital Subscriber Line (DSL)

- Digitaler Netzzugang über herkömmliche Telefonleitungen
- Datenübertragung und Telefondienst gleichzeitig nutzbar
- Realisierung durch Nutzung höherer Frequenzbereiche
- Hohe Datenraten, meist asymmetrisch (ADSL) bezüglich Up-/Downlink
- Weitere Varianten:
  - **VDSL** (Very High Bitrate): nur über kurze Entfernungen, bis 200 MBit/s
  - **SDSL** (Symmetric): gleiche Datenrate auf Up-/Downlink

![[1-dsl-aufbau.jpeg]]

Die DSL-Netzeinheit (DSL Access Multiplexer, DSLAM) ist per LWL mit dem nächsten Vermittlungsknoten verbunden. Über das vorhandene Kabelpaar (max. ca. 5 km, hohe Datenraten bis ca. 1 km) erreicht sie die DSL-Teilnehmereinheit (Splitter, Transceiver, "DSL-Modem"). Downstream sind z.B. 20 bis 200 Mbit/s möglich, Upstream ca. 1 bis 10 Mbit/s, dazu ein analoger 4-kHz-Kanal (aktuell VoIP). Beim Teilnehmer hängen WLAN, Ethernet und Telefon.

**Signaltrennung zwischen Telefon und Daten:**

- **CAS** (Carrierless Amplitude / Phase System): erste einfache Variante; feste Kanalzuordnung, klare Schutzabstände, aber wenig flexibel
- **DMT** (Discrete Multitone): aktueller Standard. Das Frequenzspektrum wird in 247 zusätzliche Datenkanäle mit je 4 kHz Bandbreite aufgeteilt, teilweise exklusiv und teilweise kombiniert für Up-/Downlink genutzt; flexibel und störsicher. DMT basiert auf denselben Prinzipien wie das fortgeschrittene Orthogonale Frequenzmultiplexverfahren (OFDM).

![[1-dsl-cas-dmt.jpeg]]

| Verfahren | 0-4 kHz | Daten |
| --- | --- | --- |
| CAS | Sprache | 25-160 kHz Uplink Data, 240 kHz bis ca. 1 MHz Downlink Data |
| DMT | Sprache | 8 kHz bis ca. 1 MHz: 247 Kanäle für Up-/Downlink Data |

### 1.3.11 Digitaler Netzzugang über Kabelmodem

Signaltrennung zwischen Kabelfernsehen und Daten:

- Umwidmung einzelner TV-Kanäle in Datenkanäle
- Rückkanalfähige Verstärker erforderlich
- Datenraten theoretisch bis ca. 36 Mbit/s, aber "Shared Medium", d.h. abhängig von der Zahl der Teilnehmer geringere Datenrate

![[1-kabelmodem-aufbau.jpeg]]

Das Kabelmodem besteht aus Tuner (Signaltrennung), Demodulator, Modulator und Medium Access Control / CPU zwischen Netz und Rechner.

0 bis ca. 1000 MHz: TV-Kanäle zu je 6-8 MHz, teilweise Umwidmung in dedizierte Datenkanäle: Uplink im Bereich bis ca. 65 MHz, Downlink oberhalb 450 MHz.

### 1.3.12 Integrated Services Digital Network (ISDN)

- Durchgängig digitale Übertragung, Sprache auf PCM-Basis: 8 kHz x 8 Bit
- Rufweiterleitung, Konferenzschaltung, Anrufbeantworter etc.
- Basis für weitere Technologien

| Anschluss | Aufbau | Datenrate |
| --- | --- | --- |
| Basiskanal | Nutzdaten, duplex | 64 kbit/s |
| Basisanschluss (S0-Schnittstelle) | 2 B-Kanäle mit je 64 kbit/s duplex (Nutzdaten) + 1 D-Kanal mit 16 kbit/s (Signalisierung) | 144 kbit/s |
| Primärmultiplexanschluss (PMX, Primary Rate Interface PRI) | 30 B-Kanäle mit je 64 kbit/s (zusammen 1920 kbit/s) + 1 Signalisierungskanal mit 64 kbit/s + 1 Synchronisationskanal mit 64 kbit/s (beide für interne Zwecke) | 2048 kbit/s |

- Der PMX gilt als **E1-Link** in Europa. Alternative: **T1-Link** in den USA mit 1544 kbit/s und einer anderen Kanalstruktur (23 Kanäle).
- ISDN hatte jedoch eher geringe Datenraten und zeitabhängige Tarife ⇒ DSL bzw. Internet-Telefonie waren sehr viel erfolgreicher.

**2G = GSM** (Global System for Mobile Communication)

- 9600 Bit/s (als Basisdatenrate) bis ca. 100 kBit/s (GPRS, General Packet Radio Service)

**3G = UMTS** (Universal Mobile Telecommunication System)

- IMT2000, DR = 0,383 bis 2 MBit/s
- Paketvermittelte Datenübertragung als Zusatz zur Telefonie; daher effiziente Ressourcennutzung
- Zusätzlich zu Frequenz- und Zeitmultiplex auch Einsatz von Codemultiplex; daher mehr Kanäle gleichzeitig übertragbar
- Erweiterungen (HSDPA, High Speed Downlink Packet Access) sogar bis ca. 10 Mbit/s

**4G = LTE** (Long-Term Evolution)

- Bis ca. 1000 Mbit/s
- Vollkommen paketvermittelte Datenübertragung, All-in-IP
- Funkzellen von ca. 10 m (Gebäude) bis zu einigen km (Land) Durchmesser; somit Anpassung an Nutzerpopulation, Zellhierarchie
- Effizientere Kanalkodierung (OFDM); neue Dienste (Videotelefonie, soziale Netzwerke)

**5G (aktuell)**

- IMT2020, DR bis ca. 10 GBit/s
- Erhöhte Qualität, Latenz 1 ms, neue Dienste (VR, Telepräsenz, IoT)
- Piloten-Einsatz in der EU, den USA, Japan und Südkorea (2018)
- Ausbau im Juli 2019 in Deutschland (Deutsche Telekom, Vodafone, Telefónica Germany) und in der Schweiz (Swisscom, Sunrise, Salt, bereits 334 5G-Türme)
- 1&1 AG hat an der Auktion für die 5G-Lizenzen teilgenommen
- Über das EU-Programm "Horizon 2020" investierte die Europäische Kommission in den 5G-Ausbau

**Zellstrukturen in Entwicklung:**

- Basis: Mikrozelle
- Interoperabilität mit weiteren Funktechnologien: Pikozellen, Makrozellen, Gigazellen
- Terrestrisch und nicht-terrestrisch: Zusammenschluss von Versorgungslücken per SAT-Funk (LEO, MEO, GEO)
- Roaming und Interoperabilität zwischen Big Players und kleineren Providern, insbesondere bei 5G

### 1.4.12 Erhöhung der Spektraleffizienz (5G and Beyond)

> [!abstract] Definition: Spektraleffizienz (SE)
> Nutzungsgrad der verfügbaren Bandbreite:
> $$SE = \frac{DR}{B} \quad [\text{Bit/s pro Hz}]$$

- $B$ = Bandbreite des Nachrichtenkanals
- $DR$ = verfügbare Datenrate im Kanal (auch $b$ = Bitrate)
- $S$ = Signalstufen pro Signalschritt ($\text{ld } S$ in Bit)
- $SNR$ = Signalleistung / Rauschleistung, oft in dB
- Beispiel: $B = 25$ MHz, $DR = 500$ MBit/s ⇒ $SE = 20$

**Nyquist-Shannon N-I/II (1948):**

$$DR < \min\left(2B \cdot \text{ld } S,\; B \cdot \text{ld}(1 + SNR)\right) \quad [\text{bit/s}]$$

Folge N-I/II: $DR \approx B/3 \cdot SNR_{dB}$ mit $SNR_{dB} = 10 \lg SNR$ [in dB]

Meinung der Folie: "Post-Shannon"? Erhöhung der SE und Minimierung der BER ⇒ Annäherung der DR an die Kanalkapazität (Shannon's Channel Capacity). Mehr dazu: https://www.gaussianwaves.com/

Die Namensgeber sind Harry Nyquist (1889-1976) und Claude Shannon (1916-2001).

## 1.5 Lokale Netze

![[1-kursuebersicht-lan.jpeg]]

### 1.5.1 Lokale Netze: Grundlagen

**Charakteristika (LAN, Local Area Network):**

- Ausdehnung max. einige Kilometer; Datenrate mind. mehrere Mbit/s
- Privates Unternehmen / Privathaushalt als Netzbetreiber ("in house")
- Rundsendekanäle (Vielfachzugriff, wahlfreier Zugriff, MAC, Medium Access Control, erforderlich)
- Einordnung in die OSI-Schichten 1 und 2

**Typische Netztechnologien:**

- Ethernet (10 Mbit/s, stochastischer Zugriff), Fast Ethernet (100 Mbit/s)
- Gigabit Ethernet (1000 Mbit/s), 10 Gigabit Ethernet (10 Gbit/s)
- 40-100GbEth (40-100 Gbit/s)
- Token Ring (4 bzw. 16 Mbit/s, deterministischer Zugriff)
- Token Bus (10 Mbit/s, deterministischer Zugriff)

In der allgemeinen Praxis sind heute nur Ethernet-Technologien relevant. Für Spezialanwendungen (z.B. Fertigungsindustrie) spielen aber auch Token-Verfahren eine Rolle.

### 1.5.2 Protokolle für den Medienzugriff

**ALOHA-System:**

- Historisches Paketfunknetz, University of Hawaii, seit 1970
- Dezentrale Stationen, Kommunikation über Zentrale
- Unkoordiniertes Wettbewerbsverfahren (stochastisch)

![[1-aloha-system.jpeg]]

- $f_1$: 407,35 MHz (Stationen ⇒ Zentrale)
- $f_2$: 413,475 MHz (Zentrale ⇒ Stationen)
- Kollision auf $f_1$ bei der Zentrale, da Senden stets möglich
- Fehlerbehandlung durch Wiederholung, falls nach Zeit $t$ keine Quittung auf $f_2$ kommt
- Kein Mithören während des Sendevorgangs

### 1.5.3 ALOHA: Beispiele

**Pure ALOHA:** max. etwa 18 % des Kanaldurchsatzes

![[1-aloha-pure.jpeg]]

Stationen A, B und C senden unkoordiniert an die Zentrale. Überlappen sich zwei Sendungen, kommt es zur vollständigen oder teilweisen Kollision (rot). Die Übertragungsverzögerung ist vernachlässigt.

**Slotted ALOHA:** max. etwa 36 % des Kanaldurchsatzes

![[1-aloha-slotted.jpeg]]

- Sendevorgang nur zu Beginn eines Takt-Slots
- Kollisionswahrscheinlichkeit etwa halbiert
- Taktung z.B. per Funk möglich

### 1.5.4 CSMA-Verfahren

> [!abstract] Definition: CSMA (Carrier Sense Multiple Access)
> Abhören vor dem Senden. Trotzdem sind Kollisionen möglich, z.B. bei gleichzeitigem Sendebeginn mehrerer Stationen (A, B, C).

- **1-persistent CSMA:** immer sendebereit, sendet sofort, sobald der Kanal frei ist
- **Nonpersistent CSMA:** der Kanal wird nicht ständig abgehört, nur zu bestimmten Zeiten; geringere Kollisionswahrscheinlichkeit
- **p-persistent CSMA (slotted):** Kanal prüfen, mit Wahrscheinlichkeit $p$ senden, sonst 1 Slot warten und erneut prüfen

### 1.5.5 CSMA/CD-Verfahren

> [!abstract] Definition: CSMA mit Collision Detection (CD)
> Mithören während des Sendevorgangs. Die Kollisionserkennung ist dadurch schneller möglich (ohne Warten auf Quittung).

Ablauf im Bus mit Stationen A und B:

1. A beginnt die Übertragung ($t_0$)

![[1-csma-cd-a-beginnt.jpeg]]

2. B beginnt mit der Übertragung ($t_0 + t_L - b$)

![[1-csma-cd-b-beginnt.jpeg]]

3. B entdeckt die Kollision ($t_0 + t_L$), stoppt die Übertragung und sendet ein "Jam-Signal". Das Jam-Signal läuft weiter.

![[1-csma-cd-b-entdeckt-jam.jpeg]]

4. A entdeckt die Kollision ($t_0 + 2t_L - b$)

![[1-csma-cd-a-entdeckt-kollision.jpeg]]

> [!tip] Merke: Für einen Sendevorgang der Dauer $2t_L$ ist eine minimale Paketlänge erforderlich, sonst endet das Senden, bevor A die Kollision bemerkt.

### 1.5.6 Ethernet: IEEE 802.3

10 Mbit/s, 1-persistent CSMA/CD. Traditionelle Lösung auf Basis von Koaxialkabel:

- **Thickwire** (gelb): Anschlüsse (Taps) alle 2,5 m möglich
- **Thinwire** (flexibler): Anschlüsse mittels T-Stecker
- Maximal 500 m pro "Segment"; Kopplung (elektrisch) durch Repeater auf Schicht 1, max. 2,5 km, max. 4 Repeater
- **Transceiver:** Kollisionserkennung
- **Interface-Karte:** Rahmenbildung, Prüfsummen

![[1-ethernet-koax-segment.jpeg]]

Kabel max. 500 m, Anschlusskabel zwischen Transceiver und Interface-Karte max. 50 m.

> [!tip] Merke: Heute werden Ethernet-Switches statt Repeater eingesetzt: individuell angekoppelte Stationen, keine Kollisionen, Kat. 5 Kabel oder höher.

### 1.5.7 Ethernet-Protokoll

Rahmenstruktur (sog. Ethernet-II-Datenblock):

![[1-ethernet-rahmen.jpeg]]

| Feld | Länge [Byte] |
| --- | --- |
| Präambel (je 10101010) | 7 |
| Start of Frame Delimiter, SFD (10101011) | 1 |
| Zieladresse | 6 |
| Quelladresse | 6 |
| Protokolltyp / Länge des Datenfeldes | 2 |
| Daten | 0-1500 |
| Pad | 0-46 |
| Prüfsumme | 4 |

- Die Präambel erlaubt die Synchronisation mit dem Empfänger.
- Der Protokolltyp gibt die Art des höheren Protokolls an (z.B. IP, IPv6, ARP etc.).
- Das Pad füllt auf die minimale Paketlänge auf, wegen des Kollisionsverfahrens.
- Prüfsumme: CRC-Code (Cyclic Redundancy Check), ohne Präambel und SFD.
- **Kollisionsbehandlung** (auch heute noch eingebaut): Warte $s$ Slots nach einer Kollision, $s$ zwischen $0$ und $2^n - 1$ bei $n$ vorherigen Kollisionen zufällig gewählt.

### 1.5.8 Switched Ethernet

![[1-switched-ethernet-csma-cd.jpeg]]

Links: Die File Server 1 bis 3 hängen mit je 10 MBit/s duplex am Ethernet Switch, an dem auch die Clients C1 bis C3 angeschlossen sind. Die Leistung beträgt dabei mehr als 60 MBit/s. Rechts: Ablauf des konventionellen CSMA/CD:

1. Station ist sendebereit (Start)
2. Leitung abhören; Leitung frei? Nein: warten gemäß Backoff-Strategie und erneut abhören
3. Daten senden, Leitung abhören
4. Kollision? Nein: fertig. Ja: JAM-Signal senden, dann wieder warten gemäß Backoff-Strategie

**Vorteile von Switched Ethernet:**

- Parallele Vermittlung aller Verkehrsströme durch Switch-Hardware
- CSMA/CD entfällt, keine Kollisionen
- Jeder Station steht die volle Ethernet-Datenrate zur Verfügung: Ethernet wird vom "Shared Medium" zum "Switched Medium"
- Aufteilung der Stationen an einem oder mehreren Switches in unterschiedliche virtuelle lokale Netze (VLAN) möglich
- VLANs wie Sicherheitszonen

### 1.5.9 Fast- / Gigabit-Ethernet

- Erhöhte Datenrate (100 Mbit/s, 1 Gbit/s bzw. 10 Gbit/s)
- Kompatibilität zu Ethernet-Konzepten
- Einsatz von Switches, Duplexbetrieb
- Verkabelung Kategorie 5 oder Lichtwellenleiter
- Segmentlänge: 100 m bei Kupferkabel, mehrere km bei Lichtwellenleiter
- 10-GBit/s-Ethernet auch für Zugangsnetze ("Ethernet in the First Mile / Last Mile") und für Weitverkehrsnetze im Einsatz; hier meist nur Lichtwellenleiter

### 1.5.13 Token Ring: IEEE 802.5

**Charakteristika:**

- Deterministisches Zugangsprotokoll, fairer Zugriff
- Prioritäten möglich

**Besonderheiten:**

- Überwachung durch "Master-Station"
- 1 Bit Puffer je Station, getrennte Anschlussleitungen für Senden und Empfangen
- Aktive Stationen (Signalverstärker)
- Weiterentwicklung: High Speed Token Ring, FDDI (Fiber Distributed Data Interface, 100 Mbit/s)

Ablauf mit den Stationen A bis D am Ring:

![[1-token-ring-ablauf.jpeg]]

1. Token frei
2. Token belegt, A sendet
3. C empfängt, der Rahmen läuft weiter
4. C empfängt noch und quittiert, A vernichtet den Rahmen, A setzt den Token auf "frei"

![[1-token-ring-quittung.jpeg]]

### 1.5.14 Token Ring: Protokoll

**Token** (je Feld 1 Byte): SD (Start Delimiter), AC (Access Control, Token-Bit = 1 bedeutet belegt, plus Prioritätsbits), ED (End Delimiter)

![[1-token-ring-token-format.jpeg]]

**Frame** [Byte]: SD (1), AC (1), ED (1), Zieladresse (6), Quelladresse (6), Daten (beliebig), Prüfsumme (4), ED (1), FS (1)

![[1-token-ring-frame-format.jpeg]]

- Prioritäten: Reservierung einer Priorität im AC-Feld möglich
- Daten beliebig, aber durch die maximale Sendezeit begrenzt
- Der Belegt-Token wird stets dem Daten-Frame vorangestellt
- Das Frame-Ende wird durch ED erkannt, daher gibt es kein Längenfeld
- Das letzte Feld **FS** (Frame Status, Rahmenstatus) ist interessant: Wegen der Ringtopologie empfängt der Sender das Paket am anderen Ende des Rings wieder. Bis dahin hat der Empfänger eine Art Quittung ins Paket geschrieben, die drei Fälle abdeckt:
  - Adressat nicht vorhanden oder nicht eingeschaltet
  - Adressat vorhanden, aber Rahmen nicht angenommen
  - Adressat vorhanden und Rahmen übernommen

Damit ist eine automatische Bestätigung für jeden Rahmen möglich.

### 1.5.15 Token Bus: IEEE 802.4

Physikalischer Bus, logischer Ring (nur für die Token-Weitergabe)

![[1-token-bus-logischer-ring.jpeg]]

Jede Station kennt ihren Vorgänger (V) und Nachfolger (N): A (V=C, N=D), D (V=A, N=B), B (V=D, N=C), C (V=B, N=A). Der logische Ring läuft also A, D, B, C, A.

**Charakteristika:**

- Realzeitfähig, Prioritäten
- Der Token muss explizit adressiert werden
- Einsatz in Fertigungssystemen; wichtigster Praxisstandard: Profibus

### 1.5.16 Typische Komponenten eines Industrienetzes

![[1-industrienetz-komponenten.jpeg]]

Eine SPS (Speicherprogrammierbare Steuerung, engl. PLC, Programmable Logic Controller) hängt an einem busförmigen Übertragungsmedium (MAC: Token-Bus-Protokoll). An den Bus sind Automatisierungsknoten (Sensoren, Aktoren) für Thermometer, Heizung, Zähler, Stellmotor, Manometer und Vakuumpumpe angeschlossen.

### 1.5.17 MAC-Verfahren

**Mehrfachzugriff auf den Kanal (Shared Medium):** Die Übertragungsmedien werden von den Teilnehmern im LAN gemeinsam genutzt. Zur fehlerfreien Übertragung muss sichergestellt werden, dass nur 1 Teilnehmer Daten sendet ⇒ Zugriffssteuerung erforderlich.

![[1-mac-verfahren-uebersicht.jpeg]]

**Zugriffskontrollverfahren (Medium Access Control):**

- **Zentral:** Die Zentrale weist sendewilligen Stationen die Kanalbelegung zu (Polling-Verfahren): Master/Slave, Beaconing, TDMA
- **Hybride**
- **Dezentral:**
  - deterministisch: Token Ring, Token Bus (sowie Master/Slave, Beaconing, TDMA)
  - stochastisch: ALOHA, Slotted ALOHA, CSMA/CD, CSMA/CA

| Art | Eigenschaft |
| --- | --- |
| Deterministisch | Konventionen regeln, wann eine Station senden darf. Der Sendebeginn erfolgt in Abstimmung mit anderen Stationen, kollisionsfrei. |
| Stochastisch | Konventionen regeln, wann eine Station senden darf. Die Stationen stehen in Konkurrenz um das Senderecht, kollisionsbehaftet. |
