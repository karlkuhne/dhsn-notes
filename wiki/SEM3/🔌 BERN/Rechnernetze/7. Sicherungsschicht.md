## 7.1 Sicherungsschicht: Aufgaben

Kommunikation zwischen Partnern im gleichen Subnetz (z.B. via Ethernet) bzw. über eine Punkt-zu-Punkt-Verbindung (z.B. PPP, Point-to-Point-Protocol, bei Modem-/ISDN-Einwahl oder via VPN, Virtuelles Privates Netz).

![[7-virtuelle-verbindung.jpeg]]

Die Sicherungsschicht (Schicht 2) stellt oberhalb des physikalischen Kanals (Schicht 1) eine virtuelle Verbindung zwischen den Partnern bereit. Die Schichten 3 bis 7 nutzen diese Verbindung.

**Funktionalität:**

- Bildung von Übertragungsrahmen zur Kontrolle von Prüfsummen
- Fehlerbehandlung (z.B. Verfälschung, Verlust, Reihenfolge, Duplikaterkennung)
- Flusskontrolle zur Überlastvermeidung
- Verbindungsverwaltung

## 7.2 Rahmenbildung

Ein Rahmen besteht aus einem Begrenzer (Flag) `01111110`, beliebigen Daten und einem weiteren Flag `01111110`.

> **Definition:** **Bitstuffing** bedeutet: Füge nach jeder fünften "1" in den Nutzdaten jeweils eine "0" ein und entferne diese wieder beim Empfänger ⇒ eindeutige Rahmenbegrenzung.

**Beispiel:** Nutzdaten `00111111001111101` im Rahmen:

```
01111110 00111111001111101 01111110
```

Nach dem Einfügen der "0" hinter jeder fünften "1" wird übertragen:

```
01111110 0011111010011111001 01111110
```

Der Empfänger entfernt die eingefügten Nullen wieder und erhält:

```
01111110 00111111001111101 01111110
```

> **Hinweis:** Die Übertragungszeile der Folie war nicht sauber lesbar. Die übertragene Bitfolge habe ich nach der Stuffing-Regel selbst berechnet.

## 7.3 Fehlerbehandlung

**Probleme:** Verfälschungen durch thermisches Rauschen, Impulsstörungen, frequenzabhängige Verzerrung etc.: Einzelbitfehler und Bündelfehler.

**Fehlererkennende Codes: Paritätssicherung** (z.B. gerade Parität)

![[7-paritaet.jpeg]]

Zu jedem Zeichen (Zeile) wird ein Paritätsbit ergänzt (**Zeichenparität**), zu jeder Spalte über alle Zeichen ein Block-Paritätsbit (**Blockparität**). Kippt ein Bit, widersprechen sich die Zeilen- und die Spaltenparität an genau einer Stelle ⇒ Fehler. Insgesamt ergibt das eine **Kreuzsicherung**. Varianten davon werden z.B. bei Internet-Protokollen in Software eingesetzt.

**Fehlerkorrigierende Codes:** Redundanz, z.B. bei Satellitenkommunikation.

Beispiel: A = 00000, B = 00111, C = 11001 (die Folie markiert B und C zusätzlich als "verboten").

> **Definition:** Die **Hamming-Distanz** $d$ ist die minimale Anzahl unterschiedlicher Bits zwischen zwei Quellcodewörtern; im Beispiel $d = 3$.

> [!formula] Erkennbare und korrigierbare Fehler
> $$ \text{erkennbar} = d - 1 \qquad \text{korrigierbar} = \left\lfloor \frac{d-1}{2} \right\rfloor $$
> - $d$: Hamming-Distanz (Anzahl Bits)
> - Anzahl erkennbarer Fehler: $d - 1$, hier also 2
> - Anzahl korrigierbarer Fehler: $\lfloor (d-1)/2 \rfloor$, hier also 1

## 7.4 Rahmenbildung: Fazit

**Warum Rahmen?**

- Strukturierung des Bitstroms in Einheiten
- Für die Einheiten gelten gleiche Regeln, gleiche Struktur, gleiche Behandlung
- Protokollsteuerdaten hinzufügen
- Ein Rahmen bildet die Einheit zur Datenübertragung, Fehlererkennung und Fehlerkorrektur
- Feingranulare Fehlerbehandlung

**Rahmenkennzeichnung:** Präambel + SFD / EFS (Blockbegrenzer, Endekennzeichnung)

**Steuerinformationen (Protocol Control Information):**

- Adressierung (meist MAC-Adressen)
- Nummerierung
- Framelänge
- Frametyp (Nutzdaten, Management, Signalisierung)
- Cyclic Redundancy Checksum (CRC)
- Die Steuerinformation steht in Header und Trailer.

Rahmenaufbau: `01111110` | Header | Nutzdaten | Trailer | `01111110`. Ein Rahmen hat eine feste maximale Länge, bspw. 1500 Bytes.

## 7.5 Protokollbeispiel: High Level Data Link Control (HDLC)

- Altes Protokoll, eingesetzt bei LAN, ISDN, GSM, X.25 und Frame Relay
- Für die IBM-Früharchitektur entwickelt; Basis für PPP und zahlreiche weitere Protokolle
- **Modi:**
  - NRM (Normal Response Mode): Polling einer Primärstation
  - ABM (Asynchronous Balanced Mode): gleichberechtigte Partnerstationen

**Bitorientiertes Protokoll:**

![[7-hdlc-rahmen.jpeg]]

| Feld | Länge [Byte] |
| --- | --- |
| Flag `01111110` | 1 |
| Adresse | 1-12 |
| Steuerung | 1 |
| Daten | variabel |
| Prüfsumme | 2 |
| Flag `01111110` | 1 |

**Rahmenarten:**

- Information
- Überwachung (verschiedene Fehlerbehandlungsprozeduren wie Reject, go-back-n etc.)
- Unnumeriert (Steuerung, Verbindungsverwaltung, Polling)

**Steuerfeld bei Informationsrahmen** (ähnlich bei Überwachungsrahmen):

![[7-hdlc-steuerfeld.jpeg]]

| Feld | Länge [Bit] | Bedeutung |
| --- | --- | --- |
| 0 | 1 | Kennung Informationsrahmen |
| SeqNo | 3 | Laufnummer 0-7 |
| P/F | 1 | Poll/Final für Polling-Steuerung |
| AckNo | 3 | Piggyback-Bestätigung |

## 7.6 Protokollbeispiel: Point-to-Point Protocol (PPP)

- Protokoll der Sicherungsschicht für den Internet-Zugang, bspw. über Modem, ISDN, xDSL
- Aushandlung von Kommunikationseigenschaften integriert (z.B. Rückruf des Einwahlknotens zur Kosteneinsparung, Sicherheitsüberprüfung, Datenkompression)
- Funktionsweise basierend auf HDLC

| Feld | Inhalt | Länge [Byte] |
| --- | --- | --- |
| Flag | `01111110` | 1 |
| Adresse | `11111111` (fest vorgegeben) | 1 |
| Steuerung | `00000011` | 1 |
| Protokollangabe | | 1 oder 2 |
| Nutzdaten | meist bis 1500 Byte | variabel |
| Prüfsumme | | |
| Flag | `01111110` | 1 |

## 7.7 HDLC vs. PPP

| Kriterium | HDLC | PPP |
| --- | --- | --- |
| Einsatz | OSI-Schicht 2; kommt aus der IBM-Früharchitektur für RN (Großrechnerwelt der IBM); gut für Telefon-/Modem-Verbindungen geeignet; Basis für PPP, aber teilweise veraltet | OSI-Schicht 2; Einwahl in das Internet über Wählleitungen zum Provider; praktikabel |
| Datenübertragung | bitorientiert, synchron | zeichenorientiert (byteorientiert), synchron und asynchron |
| Fehlererkennung / -korrektur | Bitstuffing, Frame Check Sequence (Prüfsumme CRC-16) | Bytestuffing (ESC-Sequenzen), Frame Check Sequence (Prüfsumme CRC-16) |
| Managementfunktionalität | Supervisorframes: Mitteilung der Empfangsbereitschaft / Nichtbereitschaft | **LCP** (Link Control Subprotocol) zum Aktivieren / Testen / Beenden von Verbindungen; **NCP** (Network Control Subprotocol) zugeschnitten auf die jeweiligen Protokolle der Netzwerkschicht |
