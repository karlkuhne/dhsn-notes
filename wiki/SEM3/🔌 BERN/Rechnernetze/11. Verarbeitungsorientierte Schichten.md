## 11.1 Sitzungsschicht: Kommunikationssteuerung

**L5: Session Layer**

![[11-sitzungsinstanz.jpeg]]

Die S-Instanzen tauschen S-PDUs aus. Sie greifen nach oben über den SSAP (Session Service Access Point) und nach unten über den TSAP auf die Transportschicht zu.

**Steuerung des Dialogs zwischen Benutzerprozessen:**

1. Längerfristige Sitzungen über wechselnde Transportverbindungen (bspw. mobil)
2. Interaktionsmodelle (bspw. Client/Server, Peer-to-Peer)
3. Datensicherung (bspw. synchronisierte Sicherungspunkte, verteilte Transaktionen, Backup-Strategien)

Implementierungstechnisch wird die Sitzungsschicht jedoch meist mit Mechanismen der Darstellungs- und Anwendungsschicht bzw. mit Internet-Diensten integriert.

## 11.2 Sitzungsschicht: Backup-Strategie

- Regelmäßige Datensicherungen sind eine elementare Maßnahme zur Datensicherheit. Die auf einem Speichermedium redundant gesicherten Daten werden als **Backup** bezeichnet.
- Die Wiederherstellung der Originaldaten aus einer Sicherungskopie bezeichnet man als **Restore**.
- Regelmäßige Datensicherungen sind im eigenen Datacenter oder in einer Cloud wichtig. Das Beispiel soll für die Backup-Problematik sensibilisieren.

![[11-backup-rhythmus.jpeg]]

Abwechslungsrhythmus von Voll- und Teilbackup, bspw. 20:00 Uhr täglich außer am Wochenende. **VB** = Vollbackup (freitags), **TB** = Teilbackup (Montag bis Donnerstag).

## 11.3 Teilbackup und Vollbackup

| Tag | Sicherung |
| --- | --- |
| Freitag | Vollbackup (VB) |
| Montag | Teilbackup (TB) |
| Dienstag | TB |
| Mittwoch | TB |
| Donnerstag | TB |
| Freitag | VB |

Zwei Varianten des Teilbackups:

1. **Differentiell:** Jedes TB sichert alles, was sich seit dem letzten Vollbackup geändert hat. Die Teilbackups wachsen daher von Montag bis Donnerstag (siehe Abbildung oben).
2. **Inkrementell:** Jedes TB sichert nur die Änderungen seit der letzten Sicherung (Datenträger je Tag).

## 11.4 Darstellungsschicht

**L6: Presentation Layer**

**1. Konvertierung heterogener Datenformate**

![[11-transfersyntax.jpeg]]

Statt jeder mit jedem ($n : m$ Umsetzungen) wird über eine einheitliche **Transfersyntax** übersetzt ($n : 1 : m$).

**Beispiel:**

```c
typedef struct {            // Speicherstruktur
    char name[30];          // String (ASCII/EBCDIC)
    unsigned char pixel[1000][1000];
    int resolution;         // Byteordnung und Bitordnung
} image;
```

**2. Kompression / Codecs** (im Zusammenhang mit 1.)

- Leistungsverbesserung
- Wesentlich für Multimedia und für Mobilkommunikation

**3. Schutzziele / Sicherheitsmechanismen**

- Vertraulichkeit (Verschlüsselung)
- Integrität (Prüfdaten)
- Zugriffsschutz (Authentisierung)
- Zurechenbarkeit (Digitale Unterschrift)

## 11.5 XML-Datenbeschreibung: eXtensible Markup Language

- Als einheitliche Transfersyntax empfohlen
- Abstrakte Beschreibung von Dokumenten und Datenstrukturen möglich:
  - DTD (Document Type Definition)
  - XSD (XML Schema Definition)
- Vordefinierte Sammlung vielfältiger Basisdatentypen vorhanden
- Abbildung auf Programmiersprachen mit XSL (eXtensible Stylesheet Language)

**Datentyp** (unabhängig von einer speziellen Programmiersprache):

```xml
<element name="Bestellformular">
  <complexType>
    <element name="Kundenname" type="xsd:string"/>
    <element name="Artikelnummer" type="xsd:int"/>
    <element name="Betrag" type="xsd:amount"/>
  </complexType>
</element>
```

**Instanz dieses Datentyps:**

```xml
<Bestellformular>
  <Kundenname>Ralf Muster</Kundenname>
  <Artikelnummer>17322</Artikelnummer>
  <Betrag>99.95</Betrag>
</Bestellformular>
```

## 11.7 Kompressionsverfahren: Beispiele

**Lauflängenkodierung:** Folgt in einer Zeichenfolge $n$-mal dasselbe Byte hintereinander (mit $n \geq S$; $S$ ist ein fest vorzugebender Schwellwert), ist eine kürzere Kodierung durch einen Wiederholungszähler möglich.

- Beispiel $S = 4$: Marke, $n - 4$, Byte
- 4...259 Byte sind durch 3 Byte darstellbar.
- Die Eindeutigkeit der Kodierung wird durch Bitstuffing erreicht (Verallgemeinerung der Nullenunterdrückung).

**Huffman:** Eine hohe Auftrittswahrscheinlichkeit eines Zeichens führt zu einem kürzeren Code. Man fügt jeweils die Zeichen mit kleinstem $p$ zu Teilbäumen eines linearen Binärbaums zusammen. Die Zuordnung 0/1 ist beliebig ⇒ verschiedene Codes sind möglich.

![[11-huffman-baum.jpeg]]

Beispiel mit $p(a) = 0{,}25$, $p(b) = 0{,}5$, $p(c) = 0{,}05$, $p(d) = 0{,}15$, $p(e) = 0{,}05$:

| Zeichen | Code |
| --- | --- |
| a | 10 |
| b | 0 |
| c | 1111 |
| d | 110 |
| e | 1110 |

- Mittlere Anzahl Bits pro Zeichen **ohne Huffman:** $N = \lceil \text{ld } 5 \rceil = 3$
- Mittlere Anzahl Bits pro Zeichen **mit Huffman:** $N' = 0{,}5 + 0{,}5 + 0{,}45 + 0{,}2 + 0{,}2 = 1{,}85$
- **Ersparnis:** $E = (3 - 1{,}85) / 3 = 38\,\%$

## 11.8 Beispiele von Kompressionsverfahren (Codecs)

1. **MPEG-2** (Weiterentwicklung des älteren MPEG-1-Standards)
   - Video- und Audiokodierung mit Kompression
   - Sehr gute Videoqualität, Datenraten bis ca. 50 Mbit/s
   - Anwendung: DVDs und digitales Fernsehen (DVB, Digital Video Broadcasting)
2. **H.264** (MPEG-4 Advanced Video Coding)
   - Videokompression mit besonders hoher Codiereffizienz
   - Optimierung durch Bildvorhersage (Prädiktion) und Bewegungskompensation
   - Anwendung bei Videokonferenzen und für mobile Endgeräte
3. **MP3** (MPEG-1 Audio Layer 3)
   - Verlustbehaftete Audiokompression (Entfernung nicht hörbarer Frequenzen, lautstärkenabhängige Kodierung, Weglassen von Pausen), ca. 8-300 kbit/s
   - Anwendung im Internet (Online-Tauschbörsen und -Shops), MP3-Player

## 11.10 Sicherheit bei Datenverarbeitung und Kommunikation

![[11-angriffe-netzwerke.jpeg]]

Angriffe richten sich gegen Strecken, Knoten sowie Terminals und Endgeräte der Netzwerke.

**Inhalt möglicher Angriffe:**

1. Unbefugte, unfreundliche Kenntnisnahme der Informationen (an den Knoten und Endgeräten)
2. Verfälschen von Informationen (in den Nachrichten bzw. auch von deren Absendern auf den Strecken)
3. Störungen der Verfügbarkeit (an den Knoten und Endgeräten)

## 11.11 Sicherheitsmechanismen: Kryptographie

Die Verschlüsselungsmethode ist meist fest, gesteuert durch einen veränderbaren Schlüssel.

![[11-kryptographie-prinzip.jpeg]]

- Klartext $T$ wird mit der Verschlüsselungsmethode $V$ und dem Verschlüsselungsschlüssel $K$ zum Chiffretext $C = V_K(T)$.
- Die Entschlüsselungsmethode $E$ macht daraus mit dem Entschlüsselungsschlüssel $K'$ wieder den Klartext: $T = E_{K'}(C)$, also $T = E_{K'}(V_K(T))$.
- **Symmetrische Verfahren:** $K = K'$
- **Asymmetrische Verfahren:** $K \neq K'$
- **Passiver Angriff:** Mithören des Chiffretexts. **Aktiver Angriff:** Verändern des Chiffretexts.

## 11.13 Beispiel: Caesar-Chiffre

![[11-caesar-chiffre.jpeg]]

Ein einfaches symmetrisches Verschlüsselungsverfahren, das auf der monoalphabetischen Substitution basiert (laut Caesar, 100-44 v. Chr.: $K = 3$).

$$C = V_K(T) = (T + K) \bmod 26$$

$$T = E_K(C) = (C - K) \bmod 26$$

Weiterentwicklung: Kombination von **Substitution und Transposition**.

Aufgabe der Folie: AUTO ⇒ D… Mit $K = 3$ ergibt sich A→D, U→X, T→W, O→R, also **DXWR**.
